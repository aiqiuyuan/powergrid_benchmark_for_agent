# 基础框架验收、任务认证与研究准入

初版日期：2026-10-14；实现核对更新：2026-10-15。本页回答“已经证明什么”和“还缺什么”。第三步的交付是统一合同、独立基础实现和无模型夹具；实际证据以测试输出和认证报告为准。不会把测试夹具、人工 JSON 声明或旧预实验分数写成五任务正式认证。

## 1. 四种不同的通过状态

| 层级 | 需要的证据 | 可以说什么 | 不能说什么 |
|---|---|---|---|
| 配置／文档一致 | 所有字段有定义，待定明确；版本、链接与 schema 一致 | 配置和模块合同已建立 | 某个待定 T／n／资源已经适当，任务可正式启动 |
| 本地基础层通过 | 真实执行断言、故障夹具、持久账本恢复、artifact／时钟／选择验证 | 已实现部分在测试范围内符合生命周期合同 | Harbor、模型网关、集群硬截止已经可靠 |
| Task certification | 完整真实 task 包、数据／许可／split 审计、固定镜像、checker parity、基线、校准、干净执行和重放 | 指定 task／release／资源／协议有准入证据 | 其他 task、版本或更大资源／并发自动继承 |
| 正式研究准入 | 每个目标 task certified、真实模型闭环、目标并发、批次故障／报告、预注册比较与版本冻结 | 可按冻结协议批量研究和公平排行 | 新结果可直接插入历史官方榜，或旧测试仍未曝光 |

配置字段填实只是必要条件；证据型字段还必须绑定真实输入、版本、测试和摘要。人为把状态改为 certified 不能替代认证流程。公开基础层实现的是可信协调器合同，不是任意恶意代码的安全沙箱或防伪认证系统。

## 2. 本地基础层的验收目标

下表区分已经有自动化断言的本地行为、仍需CLI证据的完整夹具，以及外部部署目标。最终执行结果在本次完成说明／测试报告中列出；真实环境工作仍阻断相应研究准入，不用本地夹具勾选代替。

|---|---|---|---|

| A02 | 缺必需文件、坏摘要、非法路径和候选合同在受理前拒绝，计数不变 | F01／F06 | RTE 必需文件闭包与干净镜像；大权重／依赖传输 |
| A03 | n=0 拒绝 protected；n=1 仅受理一次；公开 selection 不扣次数 | F04 | Harbor legacy zero 适配、工具权限与保护端实际拒绝 |
| A04 | 同 key 同内容稳定返原作业；同 key 不同内容拒绝；新 key 同内容计新次 | F10 | 网络 receipt 丢失、远端重发、多进程并发事务 |

| A08 | 截止后提交／公共选择／反馈投递拒绝；晚到结果可保存但不送达 | F08 | 开发容器、训练与子进程真正硬停止、final 访问隔离 |

| A10 | 只用截止前有效公共选择证据；并列可复查；无有效新候选按声明回退基线 | 选择差异 | 真实 task selection 成本在 T 内且结果完整；选择器公平 |

| A12 | 原始值／有效性／unknown／合法零分保留；不能直接平均不同 raw 指标 | F12 | 每家族映射与权重冻结，完整目标批次槽位覆盖 |

每项证据记录代码版本、输入／配置摘要、测试名、预期／实际结果和适用范围；仅有“脚本退出0”或截图不能代替断言。测试使用的 n／T／资源属于功能夹具，不是正式研究建议值。

## 3. 本次状态如何解释

本次基础层依照上述目标实现与测试。源码与测试已经能分别核对artifact、账本、时钟、生命周期、可信本地进程和算法ABI；完整CLI夹具与准入记录由最终验收报告给出。配置检查通过不是证书检查，只有完整task／backend验收证据才能授权生产运行。

| 能力 | 交付状态 | 解释 |
|---|---|---|
| 配置字段与执行校验 | 本地基础层范围 | 数值待定符合用户要求；研究配置不能静默执行 |
| 持久账本、时钟、快照、选择／冻结与可信本地命令执行 | 已有实现及自动化断言 | 以2.1节测试覆盖范围为准，尚无生产可用性百分比 |
| 本地审计记录 | 已有summary／jobs／attempts及冻结回执 | 全请求／拒绝日志、计划槽位、token／资源、家族聚合由入口与报告层补齐 |
| 低成本无模型 fixture | 本地完整生命周期验证范围 | 证明接口与状态语义，不包含能源物理、付费 API 或集群 |
| 五任务提交合同与公平排行路线 | 文档／结构化合同范围 | 一律区分本地复评、协议改版、历史背景和真正原赛可比性 |
| 五个真实能源 Task Adapter | 待 G2 认证 | 无新数据包、镜像／checker parity、baseline／资源校准证据，不标 certified |
| Harbor / Claude Code / 模型 Gateway 接桥 | 接口合同已明确；部署未验收 | 不声称旧实验已切换到新基础层 |
| 容器硬截止、网络隔离、broker、集群／磁盘恢复 | 外部部署待验收 | 应用拒绝截止操作不是进程硬停止证明 |
| 跨任务并发、完整批次统计与正式榜单 | 待 G3／G4 | SQLite同键事务测试不替代目标集群并发；历史98槽位保持calibration，没有启动新研究批次 |

## 4. 逐任务证书必须绑定的内容

每个 certificate 的作用范围是一个冻结的 task release、split、scorer、输入／输出合同和资源 profile；版本或其中任何字段变化都重新认证受影响项。

1. 数据与许可：真实文件清单和摘要、上游版本与归属、公开／密封／calibration 状态、合法分发范围。
2. 四角色划分：group／时序／来源关系、成员与权重、泄漏审计、密封承诺及评测端完整清单。
3. 算法产物：入口、完整依赖、权重和状态、构建方式、输入／输出 schema、训练和 reset 权限。
4. 独立评分：原始指标与方向、约束／软罚／容差、边界与非法用例、与上游 checker 的 parity 或明确适配差异。
5. 基线与校准：可信初始算法、强基线、性能 headroom、耗时／内存／磁盘／线程、反馈与终评超时。
6. 生命周期：真实 n=0 与正 n、候选失败、基础设施失败、截止、freeze、完整 final、清洁重放与账本对账。
7. 公平排行：排行榜路线、共同可比协议、算法／输出提交界限、可重评外部基线、未满足原赛条件的限制。

证书不能只包含任意填写的 `passed=true`。证据与评测代码由可信维护者保存并验证；生产部署要保护证书与版本注册表。基础实现的结构／摘要校验不能判断伪造的外部实验是否真实发生。

## 5. G1–G4 的下一次验收顺序

| 门槛 | 本次已提供的基础 | 必须补上的运行证据 | 通过后允许 |
|---|---|---|---|
| G1 最小可靠闭环 | 统一接口与本地无模型 fixture | Harbor 外部桥、真实模型工具往返、真正停止与送达证据 | 在目标执行环境迁移低成本 task |
| G2 逐任务认证 | 五 task 提交／排行合同、准入字段 | 每个真实 task 的七类证书内容，资源／超时校准 | 任务候选 release 与跨任务验收 |
| G3 跨任务批量可靠性 | 同一账本／产物／报告合同 | 目标并发、n=0及正n、故障注入、完整槽位、重放 | 冻结正式 benchmark release |
| G4 研究准入 | 固定研究与信息边界合同 | 参数／版本冻结、预注册比较和统计、独立重复计划 | 方法比较、反馈消融与 agent／演化结构研究 |

门槛失败时保留原始原因和 slot，不删除失败、换较容易数据或延长某个方法预算来宣布通过。真正的稳定性来自可解释且可复查的全流程，包括正确处理算法失败的流程。

## 6. 故障演练与生产验收最低集合

本地断言之后，在目标 Harbor／容器环境再运行：缺包启动、模型 HTTP400／断流、receipt 丢失、judge 在受理后被 kill、broker 完成但回执丢失、磁盘满、资源未供给、候选超额、等待到截止、停止后文件修改和密封访问尝试。每个场景核对应用阶段、实际进程、内容摘要、n／T、attempt 和 delivery；用量未知保持 unknown。

生产可用性目标、最大基础设施失败率和整次开发重跑上限应在资源校准后预注册，本次不填写未经测量的99%等数字。报告中完整保留算法失败与合法零分，并把基础设施缺失单列。

## 6. 追加的 broker 与真实 RTE 集成验收

新增[test_broker.py](../../tests/test_broker.py)覆盖真正的 Unix socket 往返、安全压缩包、受理前 task 校验、同键幂等、反馈聚合边界、显式 ACK 及持久恢复、超时租约和公共选择中断恢复。[test_rte.py](../../tests/test_rte.py)覆盖原生入口一致性、完整源码包、新输入执行、固定 checker 与数据、失败分类和可信执行范围。单元测试中的假 checker 只验证代码行为，不提供竞赛成绩。

真实 RTE 校准另行使用原始 checker 和四个互不重叠但历史已暴露的 A 实例，执行 n=0/n=1 共同生命周期，使用真实 UTC 墙钟、原产物冻结和新的最终输入。原始目标、输入／产物／checker 摘要与验收参数见[机器记录](../evidence/rte-lifecycle-acceptance-20261015.json)及[中文完成说明](../completion-step3-live-20261015.md)。该记录明确 model_calls=0 与 Harbor 未执行，不能代替 G1 真实模型和隔离后端门槛。
