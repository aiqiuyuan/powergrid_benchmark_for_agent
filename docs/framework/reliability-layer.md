# 统一可靠性保障层：从历史失败到可验收行为

**个人小测范围更新（2026-10-15）：** 以下是历史问题与完整保障参考，不是个人新增平台的施工清单。原生eval-in-loop已有账本、快照、恢复计时等能力；优先配置与复用，实际阻断才做局部修改，平台能力由后端维护／协作处理。以[精简设计](../decisions/0004-minimal-local-testing.md)限定当前工作，RTE最新部署证据见[完成说明](../completion-step3-cluster-20261015.md)。

初版日期：2026-10-14；实现核对更新：2026-10-15。依据：[98 个预实验槽位快照](../evidence/preliminary-experiments-20261013.md)、[F01–F12 修复清单](../implementation-plan.md)、[统一评测协议](../protocol/evaluation-protocol.md)。本页把已观察问题转为共享保障合同，并区分本地基础实现、真实 task 认证与外部部署工作。

## 1. 保障层的责任

保障层保证一次实验有可解释的开始、额度、候选、截止、最终结果和故障记录。它允许算法失败、低分和合法零分；要求框架如实保留这些结果。保障层不能通过额外评测、延长开发时间或从重放中选高分“修复”研究结果。

| 保障模块 | 最小可信记录 | 部署边界 |
|---|---|---|
| 包与配置校验 | 必需文件闭包、实际内容摘要、任务合同、准入原因 | 文件校验不证明所有动态依赖已声明；真实环境需另做清洁执行 |
| Clock / Coordinator | 一次开始／截止、不可变运行配置、阶段与恢复事件 | 应用检查能拒绝越时操作；杀停容器／资源撤销依赖平台桥 |
| Artifact Store | 相对路径、文件摘要、完整快照摘要、冻结依据 | 由可信服务写入并在读取／执行前核验；存储访问隔离由部署保证 |
| Feedback Ledger | 请求、受理、attempt、终态、送达的持久关系 | SQLite 本地事务不自动解决跨机器共享存储、领导者选举或双 judge |
| Selector / Finalizer | 截止前公共选择证据、freeze receipt、最终执行上下文 | 真实物理 scorer／密封数据／完整面板需要逐 task 认证 |
| Gateway / Executor | 模型版本、请求与重试、实际资源、进程退出／停止证据 | 本次没有调用付费模型、部署集群或证明外部服务可用性 |
| Audit | 计划槽位、所有终态、计数、raw 指标、unknown 与缺失 | 正式统计与家族归一化需预注册并填实 task release |

## 2. F01–F12 的统一关闭路径

“本地可验证”是通用程序合同的覆盖范围，不能理解为历史运行已修复或生产部署已完成。关闭某个 task 的问题还要提供该 task／版本的真实验收证据。

| 历史问题 | 证据背景 | 统一保障行为 | 本地可验证范围 | 仍需真实验收 |
|---|---|---|---|---|
| F01 包不完整 | RTE 漏掉三份必需嵌套清单，已列哈希仍通过 | 检查必需文件、路径安全、摘要和合同；不完整包启动前拒绝 | 缺文件／坏摘要／危险路径拒绝；完整夹具可以执行 | RTE 全依赖闭包、干净镜像、真实模型往返；仅补齐哈希不足 |
| F02 计时不一致 | 准备与开发起点混杂，恢复有重置风险 | 准备完成后设唯一开始／截止；恢复读取原记录 | 重启使用原截止，超时受理／投递拒绝 | Harbor、训练、judge、watchdog 全部共同计时；平台时钟变化处理 |
| F03 token 提前停止 | L2RPN、UC／HEFT 未获得原定完整 T | 正式协议禁止累计 cap、预留及基于累计量停机 | 配置拒绝累计限额；用量统计与预算分开 | 所有 agent／gateway 实际停止路径审计；单响应与供应商限流另记 |
| F04 零值歧义 | 旧内部 0=unlimited，研究 n=0 应无反馈 | n=0 受保护提交拒绝；公开检查不扣 n | 零配额和有限配额合同测试 | Harbor legacy judge 接桥；不能沿用旧零值 |
| F05 已计入但未送达 | HEFT n3／n5 计入2次仅取回1次；数值终态与账本失配 | request／accepted／attempt／terminal／delivery 分层记录 | accepted／attempt／terminal／delivery 原子持久化、未送达与晚到对账；全 request／rejected日志由入口桥补充 | 真实 agent 可见工具回执、远端 broker 恢复、读取 acknowledgment |
| F06 验证与导出候选不一致 | GOC OOM／导出缺口，静态工作目录可能变化 | 受理前持久快照；选择与终评始终绑定同一摘要 | 目录修改不影响已保存产物；坏快照不扣 n | 远端上传、存储持久性、权限隔离、完整权重／依赖归档 |
| F07 数据边界失效 | GOC 可见面板本地估分；RTE／HEFT feedback 与 final 重合 | 四角色按来源组隔离，暴露面板标 calibration | 合同／声明校验，不伪称已密封 | 真实成员审计、挂载／网络／缓存访问测试、HEFT 信息时序审计 |
| F08 截止后继续修改 | 收尾与反馈晚到可能唤醒 agent | 每次送达检查截止；先停止开发，再冻结，final 不可回流 | 晚到只留档、冻结摘要验证 | 开发容器／子进程硬停止、最终标签与日志访问隔离 |
| F09 只验静态答案 | UC 只验 schedule、HEFT 只验 bids | 终评真实执行冻结算法，再检查实际新输出 | 无静态答案资格的执行合同、命令夹具在新输入执行 | 五 task 算法入口、独立 checker、评分 parity、真实留出面板 |
| F10 重试加发预算 | receipt 丢失／重启可能重复受理 | 同 key 同内容返回原作业；异内容拒绝；同上下文增加 attempt 不加 n | 重发、内容冲突、原样 retry 与恢复计数 | 分布式进程故障注入、远端持久存储、多副本一致性 |
| F11 基础设施与候选失败混杂 | HTTP400、拉取失败、OOM、临时盘不足、作业假 Running | 类型化失败、有限且有记录重试；记录实际供给与进程开始 | 候选失败／协议错误／基础设施失败等终态分开，不静默填0 | 请求级模型恢复、镜像／集群重试、cgroup／磁盘治理、host broker |
| F12 跨任务报告缺口 | 98槽位中导出、失败、排队与完成不能混为重复 | 计划槽位与终态对账；保留 raw、零分、unknown 和版本 | 单 run 审计与夹具报告；家族聚合须遵循冻结映射 | 真实跨任务批次、方法重复／配对 seed、归一化与权重冻结 |

以上问题的“证据背景”来自固定历史快照，不能据此声称今天的远端运行仍处于同一状态。公开公式／checker 的使用合法；F07 针对的是保护面板的实际信息边界。

## 3. 提交、计数与投递必须分开

一次 protected-feedback 作业遵循以下事务边界：

1. 客户端保存稳定 submission key，提交候选快照及不可变评测上下文。
2. 服务验证路径、必需文件、摘要与候选合同。失败记 rejected，尚未受理不扣 n。
3. 先查 key：同 key 同内容返回原作业，即使 receipt 丢失；同 key 不同内容拒绝。
4. 验证时钟、额度和串行活动作业。受理与扣次原子落盘，生成固定 job ID。
5. 为执行建立 attempt，绑定 artifact／task／split／scorer／seed／资源／超时上下文。终态持久保存。
6. 写入 agent 可见通道前再次检查截止；成功送达独立落盘。无法证明实际写入时不能填 delivered。

| 情况 | 配额 | 正确处理 |
|---|---|---|
| 坏快照、缺文件、截止前未受理即拒绝 | 不扣 | 记录拒绝类型，不生成看似成功的评测分数 |
| 受理后候选语法错、崩溃、超时、不可行 | 占一次 | 候选失败，保留错误；只有 task 合同规定时才有失败分数 |
| 受理后基础设施失败 | 保留原占位 | 原上下文有限 retry，新增 attempt、不新增 accepted |
| 受理后未取回／投递失败／晚到 | 不退款 | completed 与 delivered 分开，保留具体原因 |
| 相同快照主动以新 key 再提交 | 占新一次 | 这是新实验反馈，不因内容相同免费 |
| receipt 丢失后相同 key 重发 | 不再扣 | 原 job ID／结果稳定返回，不隐式新建 |

默认每个 run 的 protected-feedback 串行：已有作业活动时拒绝新作业且不扣次。未来并行反馈要另立协议，而不是通过并发客户端绕过预算。

持久结果写入与真正跨网络送达之间可能发生故障。本地 reference implementation 记录本地交付事务；生产桥必须有稳定 delivery key 与可核对回执，不能以“已经查询”代替“已成功进入 agent 工具通道”。

当前 [Ledger](../../src/powergrid_bench/ledger.py) 持久保存作业、尝试、选择与交付凭据，`summary`给出 counted／completed／delivered／active，读取确认记 `None`。调用方需补充所有请求／拒绝的日志与次数，并把 `None`报告为 unknown。方法 `deliver`是可信协调器记录交付的接口，不能自行证明模型已获得跨网络结果。

## 4. 时钟、截止与恢复

开始／截止只建立一次，绑定不可变 run 配置。judge 或执行器普通重启读取已有时钟、计数与快照；禁止重新 `start=T` 或重建空额度。等待评测、API 重试、训练和开发期间故障均计入 T。

应用层可以拒绝截止后的新提交、选择和投递。**真正停止计算与写入是执行平台责任。** 生产接桥要将同一截止交给 host watchdog，记录容器／进程停止时间；不能在文档里把一次 deadline 校验等同 cgroup 杀停。

当前账本保存 `last_seen_at` 并采用已记录观测的最大值；一次到时拒绝后，即使调用方回拨时间，恢复也不能重新开放该预算窗口。原始 duration 单独持久保存，避免大型 UTC 时间戳相减的浮点误差改变 T。[账本测试](../../tests/test_ledger.py)与[生命周期测试](../../tests/test_lifecycle.py)覆盖这些行为。

这些检查不等于已经处理任意主机时间回拨、跨节点偏移或虚拟机暂停。部署需明确时间源、偏移阈值和异常关闭规则；发现不能解释的时钟差异应标记基础设施／协议异常，不追加时间。测试夹具可以使用可控时钟验证边界，但不能据此证明生产时钟服务。

| 恢复对象 | 可以恢复的内容 | 禁止发生的变化 |
|---|---|---|
| 普通 judge 重启 | 原数据库、job、快照、截止、terminal | n／T 重发，清除原失败记录 |
| 基础设施执行 retry | 同快照、数据、seed、scorer、资源、时限 | 换候选、换更容易面板、重采样后选好结果 |
| 开发进程 checkpoint 恢复 | 按预注册能力恢复原状态；记录来源与耗时 | 从 checkpoint 恢复却伪称全新开发，恢复期间暂停计时 |
| 整次开发重跑 | 新 run／cohort、明确恢复方式、保留旧 slot 关系 | 因某臂分低才补跑，覆盖原运行并增加独立重复数 |
| 最终评分重放 | 相同冻结产物与评测上下文，单独保存 replay | 用更好结果替换第一次有效最终成绩 |

本次的持久 ledger／artifact 恢复不自动提供 Claude Code 会话、训练优化器、人口迁移状态或跨主机 checkpoint 恢复能力；这些是 Search Backend 或平台桥的独立能力。

## 5. 选择、快照、冻结与终评

默认政策仍是 `best-public-selection`。只有 **T 内完成、有效、与具体 artifact 摘要绑定的公共选择记录**能够参与选择；并列按预声明顺序，缺有效新候选回退到冻结基线。protected 或 final 分数不得隐式成为默认选择依据。

快照至少包括真实算法入口、声明依赖、推理／求解配置、权重、允许的训练 recipe 与状态。只保存 `schedule.json`、`bids.csv` 或临时评分文件不能认证一个算法提交。每个 task 是否需要跨实例重置、模型训练状态或额外文件由 task 合同声明。

冻结后保留 selection 依据、产物摘要、task／split／协议／资源上下文以及停止证据。受信存储在读取和执行前重算摘要；检测到内容变化记录 protocol-violation，不悄悄使用变化后的文件。只读权限和哈希防止正常代码路径误改，但不能代替平台对存储管理员／恶意代码的权限边界。

终评在新的工作目录执行选中产物，按 release 逐实例提供输入，再由独立 checker 读取实际输出。命令 adapter 的本地工作目录分离与超时控制只适用于可信夹具；真实候选必须运行在已审计的容器／沙箱，控制 CPU、内存、磁盘、网络和密封数据访问。

当前 [execute_algorithm](../../src/powergrid_bench/adapters.py)要求显式 `trusted_local=True`。其请求字段检查能拒绝约定的私有标签／凭据键，但不是完整信息泄漏检测；[run_process](../../src/powergrid_bench/process.py)的进程组清理覆盖普通 POSIX 子进程，不保证清理主动脱离会话的恶意程序。checker／完整批次的截止由生产 harness另行控制。

## 6. 模型网关、broker 与资源保障的统一合同

这些接口要收敛，真实部署不在本地 fixture 通过的范围内：

| 外围能力 | 统一字段／行为 | 必須留下的部署证据 |
|---|---|---|
| Model Gateway | model／provider／client 版本分开；秘密由部署注入；有界 retry；单响应限制独立 | HTTP400 等明确错误、流式中断边界、request ID、真实用量或 unknown；无累计 cap 停机路径 |
| 数值 broker | job ID、不可变输入与候选摘要、执行上下文、终态、输出摘要 | 作业已实际开始、完整故障集覆盖、签名／可信收据与上传校验 |
| 资源控制 | 请求值、实际供给、候选峰值、超额原因、退出信号分别保存 | CPU／RAM／GPU／临时盘／线程实际限制；OOM 归因，不能只看调度器标签 |
| 截止 watchdog | 共同 deadline、终止请求、真正停止时间、剩余进程检查 | 容器、训练、子进程和写入全部停止；晚到反馈未重新开放开发 |
| 镜像／部署恢复 | 固定 image digest、清洁启动、有限拉取／传输 retry | 内容一致、失败原因、尝试记录；不能每次拉浮动 latest |

调用已经返回部分响应后的重试不能无记录地产生两条搜索分支再择优。无法保证原样恢复时保留基础设施失败并按预注册重跑规则处理。

## 7. 报告与研究语义

报告至少区分 `valid-result`、`candidate-failure`、`protocol-violation`、`infrastructure-failure` 与 pending／unstarted；token 用量不可得记 unknown，最终缺失不可直接填零。task 若规定候选超时总分为零，如历史 AHC024，应保留合法零分及超时类别。

每 run 对账 requested／counted／completed／delivered／attempts／distinct hashes。跨任务先展示 raw 和有效性；需要总分时使用冻结的任务内归一化，再按任务族预声明权重聚合。多个 GOC 规模不会自动变为多个等权任务族，£收益、优化成本和控制分数不能直接平均。

关闭 F01–F12 的证据级别与本次实际验收记录见[验收说明](acceptance.md)。真实研究准入仍需 G1 真实模型往返、G2 逐任务认证和 G3 批次／并发验收。

## 8. 本轮接桥实现与证据范围

基础版本之后新增[ExperimentBroker](../../src/powergrid_bench/broker.py)：有界 Unix socket 传输、安全算法压缩包、逐 task 受理前校验钩子、同键受理、串行反馈、受保护结果聚合白名单和显式客户端 ACK。结果查询不改变 delivered，ACK 凭据在控制器重启后保持稳定。ACK 证明客户端确认相同 payload，不证明模型已理解或读取反馈。

公共选择持久保存原始完成时间；控制器可恢复已经落盘、截止前完成的选择证据，不重新执行算法，也不重发 T/n。新的迟到选择不能借恢复进入候选集。冻结前必须调用 broker 的对账接口，未解决的执行异常应明确失败，不能悄悄回退基线。恢复入口不通过 agent socket 开放。

评测回调超时及异常路径保持执行租约，直到真实回调清理完成；Python 线程不能代替 Docker 硬停止。完整请求／拒绝入口日志、真实容器资源证据及跨主机恢复仍需外部部署验收。新增[RTE 真实题目验收](rte-integration-acceptance.md)使用固定原始 checker、真实输入和墙钟，但其可信本地执行不代表恶意候选隔离；[Harbor 接桥进度](harbor-live-acceptance.md)单独记录。
