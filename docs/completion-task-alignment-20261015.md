## 2. 已经确定的设计

五task分别为GOC、原始UC、RTE、L2RPN、HEFTCom Trading；每题n=0／1／3／5／10，各3次独立开发，共75次。开发T为43200秒共同上限，累计token无限且不使用累计token预留截断。它们是用户的研究设计，不是原赛常数或已证明统计充分的配置。n是受理上限，实际完成／取得的反馈另记。

L2RPN主线按用户确认恢复原赛动作能力，包括redispatch；375动作版本保留为受限历史／消融。每题所有方法采用相同输入、权限、资源、运行预算和评分，历史队伍分数不直接冒充本轮可比基线。公开选择的并列规则统一采用配置目录已有的earliest-completed；final只测试冻结产物。首批逐task报告原始指标，不增加跨task总分。

## 4. 怎样避免继续随意设置

原题常数按原始规则锁定；用户研究设计直接记录；共同政策在正式结果前固定；CPU／内存／逐例限额／simulate和外层timeout按固定公开或已暴露校准面板上的参考算法测量后冻结。已有旧测量只在代码、输入、环境和执行路径相同的范围内继承。

GOC旧42条阶段记录、UC两日期求解、RTE重复verifier、L2RPN三次12小时PPO、HEFT旧settlement均已核对其适用范围。没有用静态CSV的0.1秒冒充流水线成本，没有将采样内存当真实峰值，也没有从少量记录虚构p95。最终配置仍需一轮有限的无模型基线校准，不能靠75次LLM搜索反推预算。
