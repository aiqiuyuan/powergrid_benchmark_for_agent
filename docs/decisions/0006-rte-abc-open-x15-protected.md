# 决定0006：RTE开放ABC、隔离X15与两档评测

**2026-10-17更新：** 本文保留2026-10-15的v1决定。ABC／X权限、完整原题与原生框架原则继续适用；§4–5的反馈粒度、全15例有效才给分及终评时间档已由[反馈v2协议](../protocol/rte-feedback-v2.md)覆盖：900秒主评测、5400秒补充，可行例数优先、质量次之，返回完整逐例诊断。v2已通过本批真实验收并提交15组独立实验，实际启动状态见[本轮中文说明](../completion-rte-feedback-v2-launch-20261017.md)。旧七组补跑仍暂停，旧结果不改写为v2结果。

**日期：2026-10-15。范围：仅RTE任务。** 用户决定以A/B/C全部实例开放开发、X全部实例受保护评测，替代此前X04单例方案。本决定覆盖[决定0005](0005-fixed-case-evolution-first.md)中针对RTE的同case开发、禁止公开checker和禁止所有本地完整评分政策；其他四任务不随之变更。

## 1. 我们研究什么

在相同的公开开发数据、starter、模型、开发资源与12小时上限内，比较n=0／1／3／5／10次受保护反馈对最终算法的影响，每档三次独立开发。累计token不限，无累计预留截断。ABC自测允许，消耗开发时间与资源，不计n；n=0表示没有X的过程反馈，并不表示不能调试或评分ABC。

X既用于有限过程反馈，也用于冻结后评测，是**受保护的自适应评测面板**，不是未参与开发的独立测试集。最终90分钟档还衡量同一算法在更长求解预算下的表现，不以此声称独立泛化。X今天已公开，本项目亦有旧X运行记录；必须披露既往暴露，不把工作区隔离写成从未公开。

## 2. 固定数据与提交

| 环节 | 实例 | 权限和用途 |
|---|---|---|
| 开放开发 | A01—15、B01—15、C01—15，共45例 | 开发端可按需读取、运行并用官方checker自测 |
| 过程反馈 | X01—15，共15例 | 仅可信评测端持有；完整面板一次申请计一次n |
| 冻结后评测 | 同一X15 | 对截止冻结算法运行90分钟档，结果不回流 |

所有实例保留原始JSON字节和完整干预、资源、时段、情景及风险定义。原始checker固定官方commit `052def4d47271f913f89a68169083059732360f3`，不使用均值或CVaR替换原目标。提交物为`/app/submission/solver.py`，接收`--instance --output --time-limit --seed`，输出每项干预的合法开始时段；提交的是处理实例的程序。逐文件哈希、来源与输入归一化常数随task锁定，大型数据不提交GitHub。

## 3. 时间、资源和计数

- 开发上限T=43200秒，包含工具、ABC自测、训练、编译及反馈等待。开发环境与评测环境资源分别配置。
- 过程反馈每例900秒，X15实例级并行15路，评测端15 CPU计算额度；每个候选固定一个不同的可用CPU，BLAS／OpenMP默认线程数为1。这不是15颗独占物理核心的承诺。
- 900秒包括候选启动、导入、JSON解析、建模、搜索及输出；数据准备与官方checker另有监督超时。超时、崩溃、缺输出不作为有效解计分。
- 开发端2 CPU；总作业申请必须覆盖开发2＋评测15及系统余量，站点上限不得截低。内存和存储为可运行的初始配额，尚非实测结论，详见task说明。
- n沿用框架**最大受理数**，分别记录受理、完成、投递；不保证能用完。一次完整X15申请只计一次，15个内部实例不分别计数。运行中不逐例提前反馈。
- 各n档使用相同数据、资源、seed、starter及反馈schema，不通过snapshot额外免费评测或选优。
- 截止按原生artifacts冻结唯一最终版本，无修改保留starter；终评不选历史最佳候选。

## 4. 反馈与最终90分钟档

过程只返回固定汇总字段：归一化质量、有效比例、AC／WA／TLE／RE计数和约束错误计数；完整有效时提供平均原目标和风险分项。逐例目标、输入、解、原始stdout／stderr和细粒度风险不向开发端回传。内部保留逐例记录用于审计。

冻结后独立工具校验冻结源文件摘要，使用同一源码、X15和checker，每例5400秒、15路并行；与过程评分接口分开，不消耗过程n，不向agent反馈。两个时间档采用**独立启动执行**，不是同一轨迹15／90分钟checkpoint。若需要冻结算法自己的15分钟对照，必须另作不回流终验，不能拿开发期间其他版本的15分钟最好值拼接。

## 5. 分数和历史可比性

每例保留官方原始风险F与有效性。过程reward沿用已有RTE输入归一化：`q_i = 0.5 - atan(F_i / s_i) / pi`，s_i由该实例原输入的风险值与合法开始时段计算，公式和常数固定入锁；不拟合本次agent结果或历史排行榜。

沿用当前适配器的严格完整有效规则：全部15例有效时取q_i等权平均；否则面板reward为0，同时返回有效比例和失败类型。不能只平均成功例。这个reward是本地benchmark反馈，不是官方竞赛积分。最终同时保留所有逐例原目标和失败结果，90分钟reward与15分钟reward分列。

原赛完整决赛范围是C＋X30例，且存在依赖固定对手集合的积分。现在的X15、单核候选、现代依赖、独立两档执行和新数据可见性是明确的本地协议；历史逐例成绩只作参照，不授予原赛总榜名次，不直接套用0.8／0.2总榜或事后选优。

## 6. 最小实现与实际验收

复用eval-in-loop／Harbor的启动、模型、反馈计数、共同截止、artifacts和separate verifier，不增加broker、数据库或调度平台。新增一个版本化RTE task：准备ABC/X数据、实例进程并行、固定反馈入口及冻结后工具。

开发镜像不含X、旧X解或旧逐例结果。禁取官方X来源并关闭agent内置搜索；现有代理域名规则属于尽力限制，不能证明所有直接联网、镜像或模型既有知识均被隔离。正式研究须核验运行时网络通道、挂载与日志回流。源码单测、准备完整和本地非安全子进程测试不等于Linux隔离／15核整面板／真实模型端到端验收。

详细操作、资源试配和剩余条件见[任务配置与使用](../protocol/rte-abc-x15-configuration.md)。旧X04历史难度核查与结果保留在[X04说明](../protocol/rte-x04-configuration.md)，不再作为当前唯一评测case。
