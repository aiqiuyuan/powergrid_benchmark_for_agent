## 2. 共同实验语义

五项新批次均为 `n ∈ {0,1,3,5,10}`，每档 3 次独立开发，共 15 个逻辑重复；RTE 沿用其已完成的同档矩阵。**开发重复、训练 seed 和数值执行 seed 是不同层级**，不能互相替代。固定模型、数值 seed 与训练起点逐卡列明。

`n` 是受保护过程反馈的最多受理次数，不是演化代数、模型请求数、候选数量或成功反馈数。一次反馈的单位随任务而变：GOC 全 20 场景、UC 全 56 例、MAPDN 验证面板、L2RPN 全 104 周、HEFTCom 全 90 日、RTE 全 X15。应记录实际受理、完成、领取、失败与幂等读取，不能直接将不同任务相同 `n` 解读为相同信息量或算力。

开发时间 `T` 从实际就绪的开发环境开始计，包含模型调用、编译、训练、本地测试和过程反馈的排队／执行／等待。冻结预留属于 `T` 内部。提前正常返回、失败或截止可能使实际开发短于上限。各新批次不设置累计 token cap、累计 token 预留或 token 触发停止；实际用量单独记账。

每次开发结束后，认证并冻结完整代码及必要权重／状态，再独立执行最终测评。终评不占过程 `n`，不向开发回流，不用过程最好候选替换截止产物。整面板任务始终用同一 artifact；不得在实例、场景、日期或周之间拼接不同开发重复的赢家。

`n=0` 只表示没有受保护过程评分，并不表示没有训练环境、公开数据、starter、基线资料或自主估分。公开信息和禁止访问的实现／标签逐卡定义；UC 的静态校准表、RL 的共同初始权重、HEFTCom 因果历史观测，都属于必须披露的开发条件。

## 3. Baseline 与测评应如何阅读

本目录分别说明同合同重评、历史原赛记录与额外训练参考。相同输入、目标与检查器支持质量比较；历史硬件、训练成本、输入可用性或计时边界不同，仍需保留差异。共同 starter 提供统一起点，不自动成为最强 baseline。

六项任务保留各自权威指标，不强行合成一个跨任务总分：

| 任务 | 当前主测评口径 | 需要分开报告的量 |
|---|---|---|
| GOC | 硬可行覆盖、有效覆盖、硬超差、完整面板算术 mean J 的词典序 | 官方成本／软惩罚；历史几何均值差值尺度 |
| UC | 弹性模型有效覆盖、自身可信证明覆盖、family-macro 固定参考 gap、证明时间的词典序 | hard feasibility、slack、运行成本／罚分、自身／参考／native gap |
| MAPDN | 原生 CR 与平均 PL，独立完整测试面板 | 开发历史标尺与新测试锚点；无改善时 PL 归一化和综合分为 N/A |
| L2RPN | 104 周原赛组合分的等周均值；固定 baseline 差值归一化 | 原始分、存活／运行诊断、训练和推理成本 |
| HEFTCom | 完整 90 日官方 GBP 结算、缺报与资格规则 | 原报价重结算与同合同算法重跑；回放可用性假设 |
| RTE | 原赛 900／5400 s 合成目标、固定 13 队 X15 积分与 Z | 开发 reward900、可行覆盖、原始目标和固定历史比较 |

归一化中的 100 是指定参照，不是理论最优或跨任务同等难度。保留负分、超过 100、失败和 N/A 的原定义。正式结果补充时应保留每档全部三次开发的处置，明确有效覆盖、缺失和统计范围；best-of-three 必须选一份完整 artifact。
