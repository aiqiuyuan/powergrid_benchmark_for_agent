# HEFTCom：Trading 原赛期因果回放

> 本卡固定截至 2026-10-21 已冻结的任务设置，不列新一轮演化成绩。当前只参加 **Trading**；Forecasting 和 Combined 暂缓。文件名沿用任务族名称，不表示本轮提交两个赛道。

## 1. 当前版本与研究对象

本轮恢复完整 Trading 决策链：算法读取当日可见的原始天气及历史资料，允许训练发电和价格模型，并在 90 日内因果更新源码、模型和持久状态，逐日提交日前报价。旧版“预先压缩特征、固定训练截止、一次性提交全赛期报价”的实验保留为历史版本。

| 合同项 | 当前设置 |
| --- | --- |
| 协议投影标识 | `heftcom-trading-replay-v3`；公开内容为协议与元数据投影 |
| 正式冻结版本 | `heftcom-trading-replay-60h-20261021-v5` |
| 冻结源清单 SHA256 | `54b7a53b9ea9a08f7d581f6baaccd543a89892a26ebb45cb7f1dac67f6ca3248` |
| 研究变量 | n=0/1/3/5/10，每档 3 次独立开发；共同 starter、输入、资源和开发时钟 |
| 开发模型 | 固定 `bedrock/gpt-5.6-sol` |
| 最大开发时间 | 216000 秒，即 60 小时；含 75 秒冻结预留 |
| 累计 token | 不设累计额度、预留或 token 触发终止；记录实际 provider 用量 |
| 当前范围 | 90 日历史 Trading 回放；本次不使用新实验结果选任务或调资源 |

截至本卡整理时，15 个正式任务已有不同的提交身份和冻结合同；提交回执不证明所有模型已经开钟或完成终评。本目录只说明任务，不据此填成绩。

## 2. 问题、输入与输出

目标为英国混合风光组合的日前交易收益最大化。保留原赛 **2024-02-20 至 2024-05-19** 的 90 个市场日、4318 个半小时，Europe/London 前日 23:00 至当日 23:00 市场日，2024-03-31 为 46 个时段。每日提交截止为 D−1 **09:20 UTC**，报价必须有限且在 **[0,1800] MWh** 内。[组织方赛制回顾](https://arxiv.org/html/2507.01579v2)

| 输入／状态 | 算法可使用的内容 |
| --- | --- |
| 原始天气 | 已恢复的 20 个 DWD ICON-EU／NCEP GFS 文件，保留变量、格点和坐标；DWD 含风场、太阳能与需求区域，GFS 含风场与太阳能区域 |
| 历史能源与市场 | 按统一发布时间开放的风光发电、BOA、日前价和偏差价 |
| REMIT | 归档记录中可核对的发布时间／修订记录 |
| 初始模型 | 可提交经审计、仅用合法赛前数据训练的权重；保留训练截止与来源哈希 |
| 日间持久状态 | 同一次回放内保留源码、模型及 `state/`；允许增量学习、周期重训或全量重训 |
| 每日输出 | 原 Trading JSON 的 `market_day`、`submission`、`timestamp`、`market_bid`；不要求九分位数预测 |

固定入口为：

```text
python solution.py --request /input/request.json --output /output/output.json --state /workspace/state --seed 0
```

每次过程反馈及独立终评均从同一冻结源码的新副本和**空状态**开始；不同回放不继承模型更新、缓存或目标期历史。目标期已经发布的观测只在该次回放内按时到达，不导出给外层开发者。传入 seed 0，不据此保证多线程训练逐位确定。

### 数据可见性与回放假设

| 数据／边界 | 冻结规则及解释 |
| --- | --- |
| 天气可用时间 | forecast issue time +4 小时；共同回放假设，未恢复真实首次到达日志 |
| 发电、BOA、价格 | final-vintage 归档值按 valid timestamp +7 日释放；不证明最终修订值在当时已可见 |
| REMIT | 按现有 publishTime／revision；原 API 接收延迟仍未认证 |
| 每日信息快照 | D−1 09:10 UTC 固定，计算期间不刷新；对应统一 600 秒候选日预算 |
| 输入物化 | 候选启动前完成，计入整季评估时间，不计入 600 秒候选日预算 |
| 外层开发者 | 各组获得首次快照前相同的合法历史；不获取完整未来释放表、真值、Benchmark 未来报价和私有结果 |
| 缺失数据 | GFS 需求区域四段文件及部分全国预测 API 历史未取得；两家天气 2024-05-03 00Z 缺口保留，不用未来数据补齐 |
| 额外数据 | 仅允许经过审计、冻结发布时间的共同输入；候选不能联网取得事后资料 |

该版本是有明确到达假设的 **final-vintage 历史回放**。恢复原始 Trading 的日历、报价、结算及因果更新能力，不代表完整恢复原赛实时信息集；缺失的可选价格特征、历史修订及到达证据均须随比较披露。

## 4. 结算、n 次反馈与独立终评

可信端按原最终交易归档计算：

```text
generation_MWh = (Wind_MW + Solar_MW) / 2 + boa_MWh
revenue = bid * DA + (generation_MWh - bid) * (SS - 0.07 * (generation_MWh - bid))
raw_objective = sum(revenue over all 4318 periods)
```

主指标为完整精度累计 **GBP，越高越好**。BOA 的加号已逐项对账。缺失／无效的整日提交使用原归档 Benchmark 补齐，最多允许漏交 5 日；超过时可保留诊断收益，但候选不可行。原赛报告、问卷及奖项资格另行记录，不自动生成，不充当本研究数值可行性的条件。

| 环节 | 固定规则 |
| --- | --- |
| 一次反馈 | 一个不同冻结产物与固定上下文的完整 90 日／4318 期因果回放，受理后计 1 次 |
| 失败计数 | 候选错误、超时或不可行仍计数；基础设施身份及恢复收据另存 |
| 幂等 | 相同产物和上下文复用同一身份；更换客户端 key 不产生免费重跑 |
| 返回内容 | 仅 `status`、`feasible`、`score`、`raw_objective`；可行时后两者均为累计 GBP |
| 不返回内容 | 每日收益、报价、日志、路径、赛期末状态及私有归档 |
| n=0 | 不安装受保护评分桥；合法公共输入及本地开发能力与其他组相同 |
| 截止冻结 | 关闭反馈／模型入口，确认开发负载停止，捕获当前源码；不由框架选回私有得分最高的历史版本 |
| 终评 | 独立完整回放截止产物，重新空状态；不占 n，不回流开发，不接受晚到源码替换 |

原实时榜通常约滞后 7 日；本轮有意调整为**每次完整回放结束后立即返回整季累计值**，让所有 n 查询覆盖相同目标。该设置研究对同一历史赛期的有限反馈适应，不是原实时反馈制度重演，也不是未见时间段泛化。n 为允许次数上限，不保证算法能在 60 小时内用尽；反馈等待、恢复与本地训练均消耗原开发时钟。

## 5. 开发、评测与外层资源

| 层级 | 当前固定配置 |
| --- | --- |
| 开发沙箱 | 4 CPU／16 GiB；最大 60 小时；无 GPU |
| 每个候选回放容器 | 4 CPU／16 GiB、PID 上限 256、无网络；每个市场日新进程，可持久化同季状态 |
| 时间限额 | 600 秒／日，32400 秒／整季；后者含可信物化、结算及收集 |
| 外层作业 | `dev`，request=limit 9 CPU／40 GiB；专用 DinD，显式有限 Pod 父 cgroup |
| 可信运行余量 | 容量账目为 1 CPU／8 GiB；不是单独硬限或独占保留 |
| 外层 watchdog | 518400 秒，即 6 日，包含排队及启动余量；不是开发时长 |
| 打包与存储 | 初始提交最多 1024 文件／256 MiB；普通合法 Python 缓存允许，链接及特殊文件拒绝 |
| 节点存储 | Docker graph 为节点本地；临时存储 request／limit 为 128／256 GiB；CFS 保存回放及收据 |
| 运行环境 | Linux CPU、Python 3.11.16、LightGBM 4.2.0、scikit-learn 1.3.2、NumPy 1.24.4、pandas 2.0.3、SciPy 1.10.1、xarray 2023.1.0 |

镜像按内容摘要固定，不能临时联网安装。软件版本清单不是 wheel 哈希锁。4 CPU／16 GiB 子限及 9 CPU／40 GiB 共同父限具有执行效力；15 路提交不等于每个任务独占物理核或磁盘。Harbor 的 8192 MiB storage 字段没有独立硬配额，256 MiB 是初始源码包限制，均不能视为整次回放磁盘限额。

## 6. 时间估算与校准依据

| 项目 | 已测或选定值 | 用途和边界 |
| --- | --- | --- |
| 赛前原始预处理＋三模型训练 | 4 CPU 下 290.145 秒；采样峰值约 1.214 GiB | 冷训练参考，不是所有方法上界 |
| 缓存预处理表三模型重训 | 50.402 秒 | 与从原始数据处理的路径分列 |
| 原因果基线完整回放 | 816.550 秒 | 90 日、跨日状态和 DST 完整；不是正式 starter 最终配置耗时 |
| 增长数据全量重训 `E_ref` | 6684.379 秒，约 1.86 小时；90 日／270 次拟合 | 最长候选日 89.634 秒；内层无 OOM，旧外层 OOM 未知 |
| 一次反馈的正式限额 `S` | 32400 秒，即 9 小时 | 含整季受监督流程；排队、首次镜像启动等须另计 |
| 共同开发上限 `T` | 216000 秒，即 60 小时 | 含反馈等待与 75 秒冻结；10 次均达 9 小时时无法全部放入 T |
| 独立终评 | 另一次同限额完整回放，最多 9 小时加排队／编排 | 与开发时间分开，不提供额外反馈 |

开发时间按事前规则选定：研究设计给出额外研发机会 B=24 小时，`E_allow=1.5×E_ref`；`T=ceil_to_12h(10×E_allow+B+75s)=60h`。50% 为工程余量，不是统计置信区间。日限额由 `ceil_to_300s(1.5×290.145s)=600s` 得到；整季限额取 `E_allow` 和 `1.20×(90×290.145+816.550)` 的较大值，向上取整至 900 秒，得到 9 小时。第二项是静态冷流水线外推。

冻结预留按最大允许源码包的实际停止、传输和哈希耗时两倍向上取整到 15 秒；最终同源门禁实测约 36.380 秒，选定 75 秒。精确 9 CPU／40 GiB 父组的代表并发测试通过，但未测得完整 90 日并发耗时上界；旧参考的外层是 6 CPU／24 GiB，不能直接认证最终父组吞吐。

若全部 n 用满，总过程上限为 `3×(0+1+3+5+10)=57` 次回放，另有 15 次独立终评。参考回放实际分配量约 37.429 GB，逐回放规划约 2.695 TB；跨回放硬链接可能重复计量，新算法状态及日志仍会增长。该容量为规划依据，未验证 CFS trial 硬配额或 inode 容量，不能保证共享节点空闲。
