# L2RPN：IDF2023 原生 GPU RL 与混合控制

> 本卡冻结口径：2026-10-21，当前为 **IDF2023 GPU RL 24h v3**。它覆盖完整 104 周公共评测面板；旧 2020 单 episode、12 小时及受限动作实验不属于本卡。只写任务与测评设置，不填写本轮正式演化结果。

## 1. 当前版本与研究对象

| 项目 | 当前设置 |
|---|---|
| 家族 / 环境 | `l2rpn-grid-control`；L2RPN IDF2023 |
| 演化对象 | RL 算法、训练流程、策略权重、奖励/表示/课程与混合搜索，也允许其他控制算法 |
| 正式开发矩阵 | n=0/1/3/5/10，每档 3 次独立开发，共 15 次 |
| 开发上限 | 86,400 秒 / 24 小时，含 120 秒停止与冻结预留 |
| 外部模型 | `bedrock/gpt-5.6-sol`；记录实际用量，无累计 token 上限 |
| 当前正式源 | `experiments/l2rpn-idf2023-gpu-rl-24h-20261021-v3` |
| 正式源清单 SHA256 | `8f5c1988f53929f2d612431cc4940eda2007c792f18ccaf6366bec8011eab223` |
| 固定比较 | LJN Challenge、IL、PPO 在同一 public104 面板上的原生合同共同重评 |

本轮提供可实际交互的原生 Grid2Op 训练环境及 CUDA 训练能力。所有 n 组从完全相同的公开 LJN PPO 权重与混合控制器起步，比较这一共同起点之上的新增开发能力。公开 PPO 的先前训练计算量未知，不能把这段预训练算作零成本，也不能声称所有对比方法总训练算力相同。

## 2. 问题、合法信息与输出

控制器在每个原生时刻处理电网过载、故障、线路恢复、拓扑和调度等序贯决策，在安全运行、可再生能源利用及告警辅助之间取舍。环境的预测、对手、热限值、competition 难度、动作语义与 native `simulate` 保持共同重评合同。

| 阶段 | 输入与权限 | 输出 |
|---|---|---|
| 训练 | 完整原生训练环境 API；可使用 train/validation 场景与 CUDA | 自定义 RL/控制算法、训练后的权重与完整执行目录 |
| 执行 | 完整原生主观测/预测观测向量，当前步、时间、热限值元数据及原生 `observation.simulate` | 完整原生合法动作向量 |
| 入口 | `controller.py:make_agent(static_env, artifact_dir)` | 返回支持 `act / reset / seed` 的 agent |
| 终评产物 | 代码、权重、动作目录、预处理统计和全部本地依赖 | 最多 256 MiB、2048 文件/目录项；禁止链接、特殊文件及目录外依赖 |

SDK 的示例 352 动作目录仅为训练便利工具，**不限制原生动作空间**。没有额外人为 `simulate` 次数上限或逐动作时限；仍受完整周和整面板 watchdog 约束。推理端可保留仿真返回观测、复制与链式仿真语义。直接取得内部 forecast 注入，或从观测内部构造新预测环境，不在受支持接口内；所选 LJN 基线未使用这些方法。训练端则保留完整原生训练 API。

算法执行不调用外部 LLM，不读取评测原始 chronic、reference、scorer、宿主 Docker 或提供方凭据。最终推理是 CPU 推理，提交物不能依赖 CUDA 或截止后下载。权重、动作映射与预处理均参与候选身份，不能只对 Python 源码计哈希。

## 3. 训练、validation 与公共测试

| 数据角色 | 当前冻结配置 |
|---|---|
| 原生训练来源 | 官方训练归档中 832 个清洁场景 |
| 训练/验证划分 | 固定 seed=0，780 train / 52 validation；两者都可在开发时间内自由交互 |
| 数值排除审计 | 原生 float32 负荷/发电联合行与全部 104 个评测周对比，832 个均无联合行重叠 |
| 训练静态配置 | 执行副本采用任务公开 `alerts_info.json`、`config.py`、`difficulty_levels.json`，对齐告警通道、区域规则与 competition 窗口 |
| 受保护过程反馈 | 原始有序公共 104 周，固定场景/环境 seed、agent seed=0 |
| 最终面板 | 与过程反馈相同的完整公共 104 周；冻结后另行执行 |
| 时域 | 每周保留原生 2017 步时域；原生 game-over 可以提前终止并形成有效得分 |

训练静态配置覆盖不包含评测 chronic。832 个清洁训练场景的执行清单、输入来源和 train/validation 划分均保留。训练 reward、短 horizon survival 或 SDK 诊断不能替代官方最终 score。

反馈和终评使用**同一公共测试面板**。因此本实验衡量对该公开面板的适应能力；训练数据去重不使终评自动成为隐藏最终测试，也不能据此证明完全未见时期的泛化。评测进程隔离原始测试数据，是控制反馈途径的措施，不改变这些场景已经公开的事实。

## 4. baseline、锚点与可比范围

固定基线是 LJN 作者公开的 **Challenge、IL、PPO**。它们在冻结的 IDF2023 原生环境、同一有序 104 周、同 seed、同评分与 CPU 资源合同下共同重评。PPO 为三者中当前最高的实测方法，而非绝对人类 SOTA。

| 方法 | 104 周原始平均分 | 固定归一化锚点 |
|---|---:|---:|
| LJN Challenge | 61.114320596731474 | 0 |
| LJN IL | 67.1201999762473 | 86.37195740437586 |
| LJN PPO | 68.06782675776188 | 100 |

这些数字用于冻结标尺，不是本轮正式演化结果，也不是原比赛隐藏 Final 排名。比较边界包括共同电网/场景、Grid2Op 1.10.0、LightSim2Grid 0.8.2、预测/对手/热限值、动作与仿真语义、原生评分及 CPU 推理资源；GPU 用于新增训练，不用于最终推理。

**原生合同可比性通过不等于逐位复现通过。** 严格重放中 102 周动作逐位一致，两周有差异；对主要问题周，再用原基线代码、镜像、参数与资源、不经过 RPC 的原生重复运行，得到与新 RPC 流程一致的动作与分数，证明原生路径本身不保证逐位重复。另一周的小残差仍未单独归因，具体 OSQP 原因也未证明。原失败凭据保留；没有更改评分、优化器、锚点或事后设置容差。这不提供任何候选通用的数值波动上界。

## 5. n、反馈与 terminal

n 是可接受的**不同完整候选**的计费反馈次数。一次查询评测整个公共 104 周，返回有效性及聚合评分；不是一个周、一次训练 rollout 或一次动作。相同目录内容与上下文幂等；客户端换 key 不能获得免费评分。反馈领取需要 ACK，未领取不等于未占预算。

train/validation 环境交互不限次数，但始终消耗开发时间。受保护反馈的等待同样消耗原 24 小时时钟；截止后到达的反馈不能影响产物。n=0 不提供官方过程评分，而保留相同 RL 训练能力和 PPO 起点。

截止先停全部写入者，在 120 秒预留内认证当前完整代码与权重；终评使用这一当前目录，不择历史最高分候选。terminal 再运行独立完整 104 周，不消耗过程 n，也不返回开发反馈。候选错误与基础设施错误分别记录；缺失周不填 0，不发布只包含成功周的平均值，也不缩短面板来补齐分数。

## 6. 评分与归一化

官方 `ScoreL2RPN2023` 保持原生实现：

```text
weekly_score = 0.60 × operations + 0.15 × renewables + 0.25 × assistant
raw_score    = 104 个固定周 weekly_score 的等权平均
normalized   = 100 × (raw_score − 61.114320596731474)
                   / (68.06782675776188 − 61.114320596731474)
```

归一化不裁剪，可低于 0 或高于 100。保存每周完整原生分项、game-over/执行状态、动作/仿真计数与复算回执，聚合必须覆盖完整面板。survival、训练 reward 和局部 simulate 价值可作诊断，不能代替 composite。未能形成完整有效聚合时不发明最终数值。

## 7. 开发、训练与评分资源

| 层级 | 当前资源 |
|---|---|
| 开发/训练容器 | 1 张 NVIDIA A800-SXM4-80GB，4 CPU，32 GiB；CUDA PyTorch 2.1.2+cu121 与锁定原生依赖 |
| 开发外层 Job | dev，6 CPU / 40 GiB / 1 GPU；本轮合格 GPU 节点 69，专用 DinD |
| 反馈/终评候选执行 | 原冻结 CPU 镜像，24 CPU / 80 GiB，24 个并行周 worker；单 worker 一个数值线程，无 GPU |
| 评分外层 Job | 按需 center，request=limit 26 CPU / 96 GiB / 无 GPU；GPU 开发 Job 在 CPU terminal 期间仍持有原 GPU |
| 存储 | 完整提交物 256 MiB；开发存储声明 32 GiB，DinD emptyDir 80 GiB，ephemeral request/limit 128/256 GiB |

内层训练与外层可信编排资源分开；外层 CPU/内存不扩大开发者可用配额。开发无 egress/提供方凭据，CPU 候选在只读产物与受控观测 RPC 下执行，Linux 文件/网络/进程/cgroup 隔离与清理有独立验收。存储声明不保证物理磁盘空间始终充足。排队等待 GPU 不启动开发时钟，GPU 吞吐受合格卡数量限制。

## 8. 时间校准、硬上限与排队

| 项目 | 实测 / 合同及解释 |
|---|---|
| 新增开发 | 24 小时上限，含 120 秒冻结；提前正常结束可以更短 |
| GPU 短训练校准 | 1024 个原生环境步、64 次更新约 **73.059 秒**，约 14 步/秒；已验证保存与 CPU 重载 |
| 一次完整反馈/终评校准 | final v3 native n1 的两次 104 周数值 Job 分别 **1553 / 1552 秒**，约 26 分钟（含该 Job 启动/清理）；内层 24 CPU / 80 GiB；不是任意候选保证 |
| n=10 顺序反馈规划 | 仅按该面板校准，约 **4 小时 20 分钟**评分，另加排队/启动/传输；不是保证能用满十次 |
| 单周 watchdog | **86,400 秒**；原生周时域仍为 2017 步，两者不是同一单位 |
| 整面板等待上限 | **480,000 秒 = 133 小时 20 分钟**；这是保留原基线执行合同的保守上限，不是正常运行预期 |
| 外层 watchdog | **9,214,080 秒 = 106 天 15 小时 28 分钟**，其中显式队列余量 100 天 |

24 小时开发预算是综合完整面板反馈成本与可用 RL 训练吞吐后确定的；短训练校准不能外推为整天恒定吞吐，也不证明 RL 最终性能。按校准且无排队，一次用满开发额度的重复约 **24 小时 26 分钟 + 启动/冻结传输/清理**；过程反馈已经计入这 24 小时，不能再重复相加。15 次独立重复对应 15 个单 GPU 作业；同时运行才需 15 张合格卡，也可分波次复用槽位，实际排期由合格 GPU 数和 center 评分资源共同决定，不能直接将 15 次视为同一时刻完成。

极长外层 watchdog 是已有配置的故障/排队封套，**不授予 106 天开发时间，也不是完成 ETA**。最坏面板时限可以超过开发时钟；过程反馈若过晚则不可用于修改。最终 CPU grading 在截止后继续，GPU 仍被持有，因而队列规划也要考虑这段占用。
