# 五任务原题对齐、可比基准与参数依据

**RTE后续决定（2026-10-15）：** 当前RTE采用ABC45开放开发、X15隔离反馈，900秒／例、评测端15 CPU并行；冻结后5400秒／例评测且不回流。ABC允许官方checker本地自测，n仅统计完整X面板受理次数。RTE以[决定0006](../decisions/0006-rte-abc-open-x15-protected.md)和[新配置](rte-abc-x15-configuration.md)为准；下文X04单例及禁止全部本地评分条款保留为被覆盖的历史设计，其他任务不受此例外影响。

**日期：2026-10-15。状态：已完成原题差异审计及本轮设置决定；第一阶段改为五task各固定一个高难完整case，严格控制完整评分反馈次数；五任务包修改、同条件基线重跑和成本校准尚未全部完成，暂不启动75次长实验。** 本文件把[公平设置清单](../framework/fair-ranking.md)落实为逐题处理决定，不增加实验框架。

这里解决两个设计问题：哪些预实验改动改变了原问题，应该怎样处理；哪些设置可以有依据地确定，哪些必须测量后才填值。**规范确定不等于代码已实现，已有历史数值不等于新协议的合格基线。** 实际核查材料见[差异与成本证据](../evidence/task-alignment-audit-20261015.md)。

## 1. 公平基准如何建立

**当前第一阶段按[决定0005](../decisions/0005-fixed-case-evolution-first.md)执行：同case开发、计n反馈与冻结终验；跨case泛化放到下一阶段。** 下文原题恢复、信息时点和资源校准仍适用；旧四角色划分只作第二阶段参考，不是当前先跑通的前置条件。

主线保留原题的物理约束、原始目标、信息时点和合法决策范围。因小规模研究保留的现代环境、缩小实例面板、固定训练政策或输入子集，必须注明改变了什么。方法都在**本次相同条件**下重跑，才能进入本地比较。无法恢复工业数据、旧硬件或逐日原提交历史，不妨碍建立明确范围的新基准，但不能授予原赛名次。

每个task的参考表分成下列三种来源，不能合并名次：

| 参考来源 | 怎么用 | 什么情况下可比较 |
|---|---|---|
| 组织方历史榜／逐例结果 | 优先找到同一case的原始值，注明输入、时间档、资源、版本及信息差异 | 同case原始指标并列作历史参照；不同条件不授予原赛多case总榜名次 |
| 当前可执行参考算法 | 冻结源码／权重，在本轮输入、权限、资源、时间和checker下执行 | 完成真实重跑后成为本地同条件基准；未跑的方法标待复现 |
| agent开发结果 | 同starter、模型、12小时、资源、选择政策下产生的算法 | 研究n时只改变n；长期人工开发／预训练竞赛方法不冒充同T开发结果 |

原始指标优先。首批分别报告五task，不制定跨task总分。不同量纲、面板或UI reward不直接合并；参考解未证最优时，改善只能称“相对参考算法改善”，不能称optimality gap。

## 2. 四类取值依据与本轮已定设置

| 类别 | 决定依据 | 本轮处理 |
|---|---|---|
| 原题语义／常数 | 原问题、数据版本、官方checker与规则 | 按来源恢复／锁定，不能为方便运行而改变目标或物理约束 |
| 用户研究设计 | 研究什么变量、投入多少开发时间 | 直接记录下表已定值；它们不被描述成原赛规定或统计最优值 |
| 共同实验政策 | 让n的差异可解释、保证产物和结果对应 | 在看正式结果前固定，所有n执行一致 |
| 工程限额／数值设置 | 对齐检查和同平台基线测量 | 有数据才冻结；旧值只作明确标注的校准起点 |

## 3. 本轮共同政策

| 设置 | 当前决定 | 为什么这样做／落实边界 |
|---|---|---|
| case与阶段 | 每task固定一个高难完整case；开发、计数反馈、冻结复核针对同case | 第一阶段研究同case算法演化；泛化下一阶段。不能据此称未见测试 |
| 轻量自测 | 允许语法、导入、格式、接口和小型示例检查，计入T | 不得输出完整目标case分数或等价完整反馈；允许的训练loss／solver内部计算逐task说明 |
| 完整评分 | 不给开发agent完整checker，不允许本地完整目标评分、改写checker绕计数或搜索下载原赛测评源码 | 完整目标过程反馈只能走框架计数评分器；公开代码的来源身份不构成本阶段的豁免 |
| 一个反馈作业 | 同task固定同case、顺序／seed、完整执行预算、指标与反馈字段；所有n及重复一致 | n是最多受理的作业数；受理、完成、投递分别记录，不保证收到n条反馈 |
| 数据与网络权限 | 核对开发镜像、共享目录、目标输入、日志、搜索工具和出口限制 | 目标输入开发可见性逐task待定；仅有域名黑名单不能阻止本地重算目标 |
| 反馈信息 | 返回固定的运行状态、原始指标／reward、可行性及批准诊断 | schema／精度在运行前固定；不能通过stdout、原始日志或文件再泄露未经计数的目标评分 |
| 资源 | 同task各n／重复的开发和评测资源分别一致；不同task可不同 | 避免把GPU、线程或训练配额差异解释成n的作用 |
| 持续开发 | n用尽后仍允许开发至共同截止；统一停止政策 | 12小时是上限，提前结束、实际时长和续跑失败如实记录 |
| 产物选择 | 不设免费public-selection或best-public-selection评分；T内将最终版本放入原生artifacts路径 | 可依据已经消耗n的反馈决定保留版本；截止不另评分选优，无修改保留starter |
| 冻结和终验 | 截止冻结源码／参数／权重／依赖，在同case执行唯一冻结产物并独立评分 | 不占过程n，不回流开发，不按终验结果换版本。执行源码而非只读静态答案 |
| 失败与重试 | 候选错误／非法／超时按受理作业计n；基础设施原样重试不重发T/n | 是否接受incumbent由原题规则及对齐测试固定；不挑最好终验 |
| 结果 | 保存原始指标、有效性、耗时及三次独立开发结果；同case原始历史值单列 | 不只报最好一次，不把单case参照推为原赛总榜排名 |

这些是研究政策，不要求新broker、数据库或调度器。较新eval-in-loop分支已有域名egress规则和agent搜索开关；本地源码升级、实际配置与运行验收分别记录。原生入口不能提供的必要保证，通过task最小调整或后端已有能力解决，不能只靠文档宣称完成。旧四角色、独立holdout与免费public-selection仍保留历史记录，不作为本阶段默认。

| 运行环境 | 原赛旧栈与现有现代Grid2Op／LightSim不同 | 保留可运行的现代锁定环境，登记为现代重评；固定backend、热限值、冷却、对手、难度和forecast。恢复动作范围不等于已恢复旧环境全部行为 |
| scorer | 旧任务存在native经济分数、归档公式和生存率等版本 | 本轮统一锁定现代原生经济scorer及同环境reference；生存率为辅助，不混入另一版成本／terminal处理。历史公式另列parity，不替换主分数 |
| simulate和时限 | 16／步、2048／episode，5秒／步及不同初始化／episode时限是本地预算 | **不声称原赛常数**。用公开／校准面板上完整动作的Greedy／搜索／成熟控制器测成本后确定，共同限制允许上限 |
| case | 旧6／3／3已暴露；四角色有实际文件和分组审计 | 第一阶段从完整episode按难度及成本证据固定一个，seed与运行合同一致；144／48／24／96划分留作第二阶段候选，不是当前前置 |
| 基线 | 已有DoNothing／Reconnect／Greedy及公开RL_agent／binbinchen／lujixiang代码权重 | 简单方法先对账；原竞赛方法保留原动作能力，仅做披露的兼容适配，按新环境同条件复跑。375版PPO属于受限方法资产，不自动成为完整动作PPO |

[原赛组织方回顾](https://proceedings.mlr.press/v133/marot21a.html)解释原赛与评分；动作类型直接核对了原Starting Kit配置。旧四角色来自已有分组与暴露审计，留作第二阶段参考；第一阶段同episode不声称近重复排除、独立生成谱系或跨电网泛化。

**当前实现差额：** 将原动作能力接回候选／baseline执行接口；统一现代scorer及reference；固定完整episode，接通唯一计数反馈和同case冻结复核，并在完整动作路径重测simulate／逐步成本。无需新RPC服务或重训全部冠军算法。

## 8. HEFTCom：原交易语义恢复，信息和训练变体说清楚

## 10. 怎样消除“参数随意”

先用已暴露开发／校准数据，固定starter及参考算法，补必要的**无模型**执行测量；本阶段case自适应研究允许同case基线成本校准，但预算须在正式n比较前固定；不用正式n结果择预算，也不启动75次LLM搜索来猜参数。

| 参数 | 现在能确定什么 | 必须补的证据／冻结规则 |
|---|---|---|
| GOC阶段时间 | 原Real-Time 600秒＋2K秒，有原始来源 | 本平台启动／构建边界一致，完整故障在原预算下运行；不同时间档另列 |
| UC／RTE逐例预算 | 旧60秒是起点，RTE15／90是独立历史档 | 固定代表性开发实例，记录完整建模／搜索／检查的成本—可行性曲线；不能选某方法最占优的时点 |
| CPU／内存／线程 | 原成功配置可作候选，不是已证明最小配置 | 测实际配额、CPU时间、峰值／OOM和并发争用；选站点可用且能完整承载声明任务的档位，说明余量依据，不把采样下界当峰值 |
| 数值容差 | 先保留锁定原checker及模型默认语义 | 用原参考输出与非法边界样例做parity；确有数值差异才按量纲说明并全组固定，不能看到正式失败后逐方法放宽 |
| 外层verifier timeout | 必须容纳完整面板，不沿用静态CSV评分秒数 | 完整算法预算之和＋实测启动／加载／checker／写出开销；不足则调整资源／面板或另列协议，不静默截断 |
| L2RPN simulate／时限 | 16／2048等只作旧配置候选 | 在原动作范围下测参考策略质量—调用量—耗时；预算控制搜索成本而非裁掉某方法能力，所有方法同上限 |
| HEFT训练／加载／逐日时限 | 固定权重主线，真实市场日执行 | 训练、模型加载、逐日推理、settlement分别计时；旧0.1秒只读bids不作为依据 |
| case成本与最大n | 同task各n固定同一完整case作业 | 检查10次完整评分连同传输等待在12小时中的成本；若不足，统一确定执行档／算力或重新评估case，在正式结果前冻结，不针对n10裁case或改预算 |
| 模型与并发 | 模型／agent版本及单响应设置仍待锁定 | 用已验证连接核对客户端稳定性、实际配额和relay速率；按资源承载安排批次，不依据题目得分择模型 |

校准记录至少保存：task／代码／输入／checker摘要、面板角色、算法与seed、声明及实际资源、分阶段wall与CPU、内存测量方式、原始指标、完整覆盖、失败及重试。小样本只报实测范围，不伪造p95或内存峰值。现成测量及可继承范围见[成本证据表](../evidence/task-alignment-audit-20261015.md#3-已有成本证据能支持什么)。

## 11. 进入75次实验前的收口条件

1. 每task固定一个高难完整case，记录选择依据、原题／变体边界、开发可见数据、算法入口、指标与失败规则；第一阶段三阶段同case，跨case泛化不作为前置。
2. 不给开发agent完整checker／目标评分工具，禁止搜索下载原赛测评源码；检查镜像、共享路径、日志、目标数据及现有网络／搜索限制，确认所有完整目标过程反馈只走计n入口。仅有黑名单字段不算验收。
3. 每题starter和至少一份完整参考算法在本轮合同下实际执行并独立评分；原题目标、约束与数值规则对账有证据。
4. 资源、单例／阶段限额、反馈schema及seed有测量依据；T/n/token/repetitions采用用户已定值，旧题面／launcher硬编码同步。模型等待定项在正式比较前冻结。
5. 原生短验确认n0无完整目标过程反馈、正n可提交／取回、超额拒绝与失败计数；T截止冻结artifacts最终版本，同case独立复核不回流开发，没有免费selection或终验选优旁路。
6. 冻结75项运行清单及版本。开始后发现实质错误则升协议版本并重跑受影响整组，保留旧结果，不按n效果选择性修补。

**已完成政策整理和只读审计，不等于五任务已实现／校准或生成公平新分数。** 当前先落实RTE X_04的必要任务修改及配置核验，再逐题推进；实际完成范围见[本轮中文说明](../completion-fixed-case-20261015.md)。代码只处理具体差额，不继续扩建通用框架。
