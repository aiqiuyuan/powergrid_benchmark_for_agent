# UC：参考质量下的求解加速合同

日期：2026-10-15。状态：设计与配置准备，`release_ready=false`。主入口是[UC/SCUC task card §13](../task-cards/unit-commitment.md#13-文献对齐的研究目标与配置2026-10-15)，参数文件是[unit-commitment-speed.design.json](../../configs/unit-commitment-speed.design.json)。该JSON是task专用准备参数，不是旧49字段配置验证器或eval-in-loop可以直接提交的运行配置；接线和实际验收尚未完成。

## 1. 研究问题与适用范围

上层问题：相同开发预算下，更多计n反馈是否帮助Agent开发出更高效的UC求解算法。下层任务：对固定完整UC case，在保持原约束的条件下，更快达到同一个参考质量标准。

第一阶段沿用[决定0005](../decisions/0005-fixed-case-evolution-first.md)：开发43200秒，n=0/1/3/5/10，每条件3次独立开发，无累计token cap；同case反馈与冻结后复核。n=0无过程完整目标评分，其他条件的完整评分通过框架计数；无免费public-selection。截止冻结最终artifacts，不用终评挑版本。不同case泛化是第二阶段研究。

完整目标输入的可见范围、开发镜像/网络和评分旁路尚需审计。仅不提供checker不能证明严格n成立；标准数学求解器在可信评分执行中计算内部目标是正常求解行为。

## 2. 预算、参考和达标

准备档为RTS/CA每例300秒、FERC每例600秒，均包含候选的加载、建模、实例相关预处理、JIT、优化、修复和输出。一个case只冻结一个主档，各n一致。1200秒是校准失败时可考虑的新准备版本，不是运行中自动延时。记录60/120/300/600秒中不超过主时限的轨迹点，注明这是同一长预算策略的前缀，不声称独立短预算成绩。

所有算法使用同一个在开发前冻结的参考上界U和原问题有效下界L。参考准备每方法每case最多14400秒。主目标epsilon=0.001（0.1%），要求参考gap不超过0.0001（0.01%）；补充epsilon=0.0001（0.01%）仅在参考gap不超过0.00001（0.001%）时开启。这一10倍参考裕量是本项目准备政策。参考达不到门槛时暂停速度主榜准备，记录失败，不能称为算法未达质量；可另报成本诊断，或在Agent实验前修订发布版本。

独立checker从排程重算成本C与可行性。原始公共下界gap为`g=(C-L)/max(1,abs(C))`。数值准备值为成本裕量`tau=max(0.01,1e-6*abs(U))`；仅在`(C+tau-L)/max(1,abs(C+tau)) <= epsilon`时判定达标，避免成本容差边缘触发时间奖励。原始g仍报告。C显著低于L则暂停该case评分并核查模型/参考；容差内的负gap标记为数值情况，不宣称超越最优。

二元变量精确为0或1；连续量有限；MW残差准备容差为`1e-5+1e-8*max(1,声明的物理尺度)`。逻辑、数组长度、时段索引与完整备用不放宽。这些值必须经合法解、边界反例和跨formulation parity验证后统一冻结，不为接纳某候选扩大。

本主榜测量“达到独立参考质量的时间”。离线L不提供给候选，也不计入在线时间；候选无需自己证明最优性。因此本榜不声称加速了原问题最优性证明。证明时间须用可信的完整原问题上下界另设赛道，不能采用变量固定子问题的下界冒充原问题下界。

## 3. 时间与失败

每次重放使用新进程和目录，候选1 CPU、1 solver线程、8192MiB、无GPU；BLAS和子进程一并受限。该资源是准备选择，不是已通过校准的论文复现。依赖可在统一镜像预编译；候选特有构建/训练占开发时间，实例相关JIT占在线时间。不得跨重放读取可写答案缓存。

最多64个完整原子快照，每个16MiB。可信端接收不可变副本并记录时间，之后独立验解；第一个达标快照的接收时间为t。候选自行报告的成本、下界、时间戳和状态无权威性。在线输出成本计时，独立checker计时另报。

候选进程组在T_exec截止。正常到时且有截止前的合法incumbent可计分；崩溃/OOM/资源违规为候选失败。基础设施故障不算候选失败，只原样有限重试，不挑更好随机结果。显著参考不一致属于评测准备问题，不给某方法单独判失败。

checker每次调用总预算准备值120秒，另外预留排队/启动60秒，因此单次反馈作业上限准备值为`T_exec+180`。这不是候选额外求解时间。验证器不能完成合法快照检查或排队超限须按基础设施异常处理并审计，不能冒充候选无解。所有开销仍占Agent开发墙钟。

## 4. Reward与排名

反馈每次受理运行1个固定case、solver seed=0；终评运行同case的3次独立重放，solver seeds=0/1/2。所有基线按相同种子配对，方法顺序随机化，不超售CPU。3次终评重放衡量运行稳定性，不是3个独立开发实验或3个新实例。

对每次重放j，达标则`p_j=t_j`；未达标则`p_j=2*T_exec`，无解/非法/候选运行失败也计该罚时，永不删分母。`PAR2=mean(p_j)`。全部重放均有合法排程且没有候选运行失败时获得可行性资格：

`Reward = 1 - PAR2/(2*T_exec)`。

未获得可行性资格则`Reward=0`。所有重放均合法但都未达标，Reward也为0；原始状态必须区分这两种情况。正式排名先看可行性资格，再按PAR2升序；达标率、每次用时/状态和固定预算成本分列，**不另把达标率放在PAR2之前排序**，以保持主指标与Reward一致。不存在对成本和速度另配权重的总分。

例如T_exec=300秒：30秒达标得0.95，150秒得0.75，300秒得0.5，未达标得0。三次均合法、时间为30/150/未达标时，PAR2为260秒、Reward为0.566667；任何一次非法则资格失败、正式Reward为0。不能选最好的重放或只在共同成功子集计算加速比。

终评保留全部精度；毫秒级差异不能单独证明加速。报告三次开发逐次结果、全部重放、与同机强基线的配对差异及变异程度；3次开发不保证显著性功效，不能把重放数量充当独立样本量。

## 5. 反馈和冻结

反馈schema固定为status、feasible、target_hit、penalized_seconds、reference_gap、reward、failure_category。罚时保留3位小数，gap以比例保留6位小数，Reward从已投递的舍入罚时计算；未通过可行性时Reward=0、gap=null。完整内部值留档。不得通过第二字段或日志补出更多私有精度。

reference_gap对应截止前接收并通过独立验证的最低成本快照，无合法快照时为null；首次达标时间仍取最早达标快照的接收时间，二者分别计算。

不返回私有输入/排程、原始日志、U/L、文件路径或堆栈。受理原子计n，重发用幂等键；候选错误或超额请求的处理沿用共同政策。反馈等待占43200秒；迟到反馈只归档，冻结后终评不回流开发。
