# 后续实施顺序、待定项与验收矩阵

**状态：v0.1-design 的实施与认证计划；不是已完成的软件验收报告。日期：2026-10-14。**

初版完成前两步文档建设。**2026-10-15新增第三步合同与本地基础实现，见[完成说明](completion-step3-20261015.md)。** G1的无模型参考闭环已有证据；真实Harbor／模型往返、平台硬停止与投递仍待验收，G1整体及G2–G4尚未通过。这里保留完整研究发布门槛，让“稳定基础框架”“稳定task”“可批量测试”具有具体判断依据。

## 1. 实施顺序与停止条件

| 阶段 / 门槛 | 先做什么 | 必须交付的证据 | 通过后才能做什么 |
|---|---|---|---|
| G0：文档契约 | 统一范围、术语、任务卡、信息边界、预算、产物和失败语义 | 当前仓库的规格、协议、ADR、设计清单；内部一致性检查 | 按相同合同实现框架和 task |
| G1：框架最小可靠闭环 | 完整任务包 → 共同计时 → 候选快照 → 受理/执行/投递 → 截止冻结 → 执行终评 | 小任务/测试夹具的端到端记录；无模型链路与真实模型工具往返各一次 | 迁移能源任务和校准资源 |
| G2：逐任务认证 | 数据/许可审计、独立 split、冻结 baseline、真实算法入口、checker、资源校准 | 每家族 task release 候选、基线表、容差、故障测试与清洁环境执行 | 目标并发与跨任务验收 |
| G3：跨任务批量可靠性 | 使用目标并发，覆盖 n=0 与至少一个正 n、失败和恢复 | 批次覆盖表、账本对账、实际冻结/反馈时间、重放结果 | 填实全部清单并冻结正式 release |
| G4：正式研究准入 | 版本冻结、预注册比较与统计、统一资源和 seed | 真实 release manifest、主要假设、比较矩阵和分析规则 | 方法基线、反馈消融、结构消融与论文结论 |

任何门槛失败，记录具体问题并修复，不能通过删除失败结果、改名密封面板或缩短任务覆盖来宣布通过。若改变资源/接口/数据/评分，需要新候选版本并重做受影响验收。

## 2. 基础框架修复清单

以下优先级来自已经观察到的缺口。责任角色是建议分工，不代表已经指定实际维护人。

| ID / 优先级 | 问题与目标行为 | 建议责任 | 可关闭问题的证据 |
|---|---|---|---|
| F01 / P0 | RTE 类任务包缺必需嵌套文件；校验完整依赖闭包，拒绝不完整包 | task packaging | 删除任一必需文件都在启动前失败；干净环境解包可执行；只校验已列哈希不算通过 |
| F02 / P0 | 计时起点与恢复不一致；统一准备完成后的 T，训练/等待均计入 | coordinator | 同一开始/截止时间贯穿 agent/judge/watchdog；重启不重置；准备不能提前搜索 |
| F03 / P0 | 累计 token 守卫提前停；迁移到无累计 cap | agent runtime | 无累计限额/预留/停止路径；单响应限制独立；极高累计用量仍按 T 截止 |
| F04 / P0 | n=0 与旧内部 unlimited=0 冲突 | evaluator adapter | n=0 无法受理 protected-feedback；公开测试仍可用；显式 unlimited 模式不混用 |
| F05 / P0 | 计入但未送达、数值作业完成账本仍 running | feedback ledger | 每个作业 request/accepted/attempt/terminal/delivery 可对账，实际次数和 receipt 不丢失 |
| F06 / P0 | 快照失败或终评导出丢失；验证/执行不是同一候选 | artifact storage | 受理前快照成功；上传/内容摘要匹配；选中产物持久保存；旧目录变化不影响终评 |
| F07 / P0 | 受保护与 final 数据重合或可直接读 | data isolation | 四角色清单分组审计；开发端不能读保护成员/标签/缓存；公开 checker 保持可用 |
| F08 / P0 | 截止后反馈或收尾重新修改算法 | deadline/freeze | 截止停止写入；晚到结果留档但不投递；final 前不可变 freeze receipt |
| F09 / P0 | UC/SCUC、HEFT 只验静态输出 | task evaluator | 冻结算法在新输入上执行；静态旧结果不可直接作正式提交；checker 独立重算 |
| F10 / P1 | 重试重复受理、服务恢复增发预算 | evaluator recovery | 相同 submission key 原样返回；同键不同内容拒绝；原样重试不二次扣 n；重跑 cohort 明确 |
| F11 / P1 | API400、镜像拉取、OOM、临时存储和进程终态混杂 | infrastructure | 有限且可记录的重试；资源供给与候选超额可区分；退出状态可对账；不复制候选获取更高随机分 |
| F12 / P1 | 跨任务报告缺失/失败分类不一致 | results pipeline | 自动核对计划、运行、有效、失败、缺失；raw 指标、合法零分和实际预算不被删改 |

P0 全部通过后才迁移到正式批量研究。P1 同样是 release 前要求；P0/P1 仅表示施工顺序。GOC30000 的大型恢复可以晚于中等规模核心 task，但不能用其部分计算成果替代完整终评。

## 3. 五个任务族下一份交付物

| 任务族 | 优先交付 | 重点校准 | 主线准入条件 |
|---|---|---|---|
| GOC | 中等规模 solver 执行包、完整故障 checker、网络来源分组清单 | Code1/Code2 全批耗时、内存、参考目标、软罚/硬约束容差、核心规模 | 在目标资源下完整覆盖故障且重放成功；固定场景优化与跨场景 claim 分开 |
| UC | 标准 UC 输入→求解器→schedule→独立checker；SCUC 单独适配声明 | 小/中/大实例难度、solver 许可、初始与强基线、改进空间、容差 | 新实例执行有效且可区分实质改进；受限 SCUC 不冒称完整物理模型 |
| RTE | 必需文件闭包与清洁环境入口；独立新实例排程 | 60秒先导预算是否合理、规模/风险分层、公开/保护实例覆盖 | 修复包完成真实模型往返、反馈与终评；不是只通过包哈希 |
| L2RPN | 锁定环境/动作/backend/scorer、场景组关系、控制器加载与 episode 执行 | 场景成本、训练质量、simulate 限额、步/episode 超时、CPU/GPU赛道 | 评分 parity 与重放通过；全部方法独立终评；统计配对权重与 episode 关系 |
| HEFTCom | 冻结预测/报价管线执行包、可用时序审计、独立新时期清单 | 特征 issue/公布滞后、时间间隔、训练/推理限额、收益风险和合理强基线 | 训练边界无泄漏、报价可重算、final 未作反馈、代码执行与权重可重放 |

旧 RTE 包修复、HEFT 的24项本地时间政策检查和 GOC 的局部收尾修复均只证明各自记录中的验证范围；不能推定这些门槛已全面通过。L2RPN 已导出20份策略的补充终评属于旧协议证据完善，仍与未来无累计 cap 的正式比较分开。

## 4. 参数校准与必须关闭的待定项

| 待定项 | 决定方法 | 冻结位置 / 禁止做法 |
|---|---|---|
| 核心实例、数量、时间期与 group | 审计来源/曝光/相关性，再建立开发→选择→反馈→最终分组 | split manifest；不凭文件随机拆分，不复用已暴露 final 名称 |
| 数据/代码/模型/solver 许可与归属 | 各上游来源分别核对，记录适配差异 | task release；不把全部资产统一标成未经核验许可 |
| 开发 T、CPU/RAM/GPU、磁盘/线程 | 简单与强基线在 calibration 面板测成本，预留已说明安全余量 | resource profile；不按某方法已取得成绩回头调预算 |
| 构建/反馈/逐实例/最终批次时限 | 测完整任务生命周期与高分位成本，识别启动与算法执行成本 | task manifest；不把开发时限当最终算法超时 |
| baseline 与归一化 | 固定可信初始算法与合理强基线，衡量 headroom 和数值下限 | baseline artifacts + scorer config；不人为削弱基线、不冒称最优 |
| 硬约束、软惩罚、容差与失败分数 | 用官方定义和无效/边界夹具验证，排查数值不一致 | evaluator config；不让 task 自报分替代独立检查 |
| selection、反馈字段与截断 | 主线 best-public-selection；统一每任务反馈信息 | protocol release；不在组间悄悄增加诊断内容 |
| 模型政策、工具、依赖与缓存 | 固定可用模型标识、单响应限制、外部信息与预训练策略 | run/task manifest；无累计 cap 不等于无资源约束 |
| seed 与正式重复数 | 校准方差/成功率，预注册 paired seeds、不确定性分析 | experiment preregistration；不把场景/控制步当更多独立开发 |
| 恢复与测试曝光 | 原样重试条件、整个开发重跑规则、final 轮换/更新 | cohort/protocol记录；不选择较好重放结果、不事后改历史 |

清单中的 `null` 表示未冻结，没有默认回填值；模板不应被运行器当作可执行配置。正式 release 准入应拒绝缺字段、非实测预算或伪造摘要的声明。

## 5. 契约验收矩阵

每项记录任务/版本、输入夹具、预期行为、实际行为、时间/哈希、通过与否及缺陷链接。低成本夹具验证框架语义；真实 task 校准验证物理/业务正确性，二者不能互相替代。

| 验收项 | 必须出现的用例 | 通过标准 |
|---|---|---|
| 包与环境 | 完整包、缺必需文件、错摘要、缺依赖、镜像未准备好；绝对路径、../穿越与越界软/硬链接 | 问题在开发启动前可解释地拒绝；解包不越界；干净环境成功，不靠开发机残留 |
| 四角色与信息时序 | 同源样本、重叠窗口、保护目录/缓存、HEFT未来特征 | 分组审计无意外跨角色；合法当前信息明确；越界访问拒绝并记录 |
| 反馈预算 | n=0；n=1首个成功/候选失败；第二个拒绝；未取回；同内容新提交 | 受理计数符合规则，失败和未送达不退配额，正常公开检查不扣 n |
| 幂等性与重试 | receipt 丢失、请求重发、同键不同内容、评测基础设施故障 | 不重复受理；相同作业原样恢复，attempt 增加但 n 不增；差异拒绝 |
| 截止 | 等待期间到时、结果在截止前/后、冻结目录被修改、judge重启 | 共同时钟不变；晚到不投递；选中冻结产物保持一致；无额外开发 |
| token 政策 | 高累计用量、单响应限制、用量未知 | 不因累计量结束；响应限制仍生效；unknown 不填零 |
| 算法执行 | UC/HEFT只有静态答案、合法求解代码、非法/超时/NaN/缺输出 | 正式算法入口真实执行；独立验证；静态历史仅 calibration |
| 评分 | 原始目标、硬违规、合法软罚、容差边界、合法零分 | 符合任务语义；原始值与映射可核对；不放宽高分候选规则 |
| 选择与状态 | 公共选择并列、无有效候选、未完成选择、episode间缓存 | 预声明并列/基线回退；只选 T 内完整结果；按release重置 |
| 故障与批次 | candidate超额、平台未供资源、未启动、补跑、模型错误 | 分类与原始证据一致；计划槽位完整覆盖；重跑不静默替代旧记录 |
| 重放 | 新目录/进程执行，依赖/数据/seed/资源固定 | 满足任务容差或预注册随机性标准；不替换第一次有效成绩 |
| 目标并发 | 每家族 n=0 与正n、混合成功/失败、队列与磁盘压力 | 全部状态与receipt可对账，无丢产物/重复计数/失控进程/跨run数据污染 |

## 6. 稳定性的报告方式

首次认证批次完整公布计划槽位和目标并发，报告启动成功率、算法有效率、基础设施失败率、反馈送达率、终态对账率、产物留存率与重放一致性。候选可以合法失败或零分；稳定框架必须正确保留和分类这些结果。

正式 release 的契约用例必须全部通过，所有认证记录必须能对账，不能有未解释的产物丢失、重复扣次或越界反馈。大批运行的可用性目标、最大基础设施失败比例与故障重跑上限，需在 G2 成本校准后预注册；本次不声称已测得 99% 等可用性指标。每个家族至少覆盖清洁环境真实算法执行、n=0和正n、非法产物与一次重放；主方法研究的独立重复数另按研究契约规划。

当失败率明显干扰比较，先修可靠性再增加方法臂。高分案例和“集群任务显示完成”都不能替代以上发布证据。

## 7. 正式研究的最小顺序

1. 固定一个低成本认证夹具和一个能源 task，验证框架的真实模型闭环；随后五家族逐个认证。
2. 发布所有任务的初始/传统强基线与资源校准记录；冻结核心 release。
3. 用同一模型与总资源，做 n=0/1/3/5 的小矩阵，先核对实际送达、有效率和方差。
4. 在校准后选定正式主要比较，运行独立开发 seed；按预注册分析报告每家族终评与泛化差距。
5. 再扩展 agent 组织、记忆、工具规划、人口/选择/变异机制；每次明确变动变量与复用测试的曝光限制。
6. 高成本 GOC30000、多拓扑、GPU赛道、在线LLM控制与滚动重训逐一另立扩展协议。

这份计划使后续施工与研究可以追踪，但上述运行步骤本次尚未执行。
