# 机组组合：UC 核心与 SCUC 扩展

> 状态：UC/SCUC已有小面板先导；v0.1通用求解器与独立划分协议为拟定，尚未验收。历史证据截止北京时间 2026-10-13 23:32；修复准备核对至 23:38。

## 1. 家族定位与研究能力

**家族 ID：`unit-commitment`。** UC为初始核心任务，SCUC为家族扩展。任务研究混合整数优化、启停与爬坡等跨期约束、松弛与分解、暖启动、可行性修复，以及固定求解时间内的质量提升。UC和SCUC不能在“五个家族”的计数中各占一项。

UC采用PGLib-UC的铜板网络实例。现有SCUC是派生的预防式DC线路约束版本，必须按适配定义命名；不能称完整AC或完整N−1 SCUC。

## 2. 演化对象与执行合同

- 演化对象：从标准实例输入生成排程的通用求解器代码、MILP建模、求解策略、初始化及后处理。固定预算内的结果可包含非最优的有效 incumbent。
- 提交产物：源码、依赖锁定、参数与随机种子；可包含公开训练数据产生的学习组件及其训练配方。禁止用按留出实例ID检索的预存排程替代求解。
- v0.1终评在新实例上**重新执行冻结求解器**，再由独立 verifier 检查排程并重算成本。现有先导 grader只解析排程，尚不满足此泛化合同。
- 指标：每例成本、可行率、参考 gap、求解时间、峰值内存及可获得时的有效下界。约束容差和缺失字段处理须固定；约10⁻⁷变化不能不经容差分析就称实质改进。
- 不同求解器的许可与资源须披露。跨实例主指标可采用相对固定参考成本的聚合，但同时提供原始成本、失败和未证明最优状态。

## 3. 已有预实验与限制

| 项目 | 已观测设置 |
|---|---|
| UC先导 | 2个完整48小时RTS实例：2020-01-27与2020-07-06；73台火电、81台可再生机组；输入全部公开 |
| SCUC先导 | 14/30母线，5/6台火电机组，两个完整36小时实例；逐时19/38个非孤岛线路故障 |
| SCUC适配 | 普通限额100 MW、紧急限额120 MW；不含孤岛线路、机组故障、纠正重调度、AC无功或负荷切除 |
| 依赖与基线 | Julia 1.10.11、UnitCommitment.jl 0.4.0、JuMP、HiGHS；单线程，种子20261012；每例60秒MIP求解，不含准备编译 |
| 演化条件 | 每任务n=0/1/3各1次，30分钟开发；旧版累计token cap为100万；开发3 CPU/8 GiB，评测1 CPU/2 GiB |

| 条件 | UC面板平均相对成本 | SCUC面板平均相对成本 | 实际反馈计数/取回 |
|---|---:|---:|---|
| n=0 | 1.000000000 | 1.000000000 | 两者0/0 |
| n=1 | 1.000000000 | 0.999999897 | 两者0/0 |
| n=3 | 0.994570407 | 0.999999892 | UC 0/0；SCUC 1/1 |

6次最终排程均有效。UC n=3面板平均相对成本下降约0.5430%；1月成本由1,249,271.762990降至1,235,705.689765，7月参考成本保持不变。SCUC改善接近数值容差，尚无实质收益证据。

全部6次因token守卫提前结束，实际开发3.13–11.65分钟。UC的公开本地grade可算完整目标；其“n预算”没有限制等价的实例成本信息。此批是**固定可见面板的自适应优化先导**，不是受保护信息效果或留出实例泛化的正式结论。

## 4. v0.1 数据与反馈协议（拟定）

| 数据角色 | 拟定安排 |
|---|---|
| Public development | 公开实例与完整约束/目标，可运行独立checker和训练组件；公开数据内的求解迭代不计n |
| Public selection | 独立公开场景，按照固定质量与可行性规则选候选 |
| Protected feedback | 独立日期、负荷/可再生情景或系统组，输入仅在服务内；每次运行候选并返回预定聚合指标 |
| Final test | 未用于开发、选择或反馈的实例组；冻结后运行算法，独立验收 |

按底层系统与时间情景分组，先说明评测同系统新日期还是跨系统迁移。避免相邻日期或近复制场景跨组。旧两例和派生小网络用于开发/校准；不重新宣称其为未触碰测试。实例清单、派生规则、组大小及许可**待校准与来源核验后冻结**。

PGLib-UC原数据公开，因此保护的是实验期访问与候选结果，不保证模型从未见过历史实例。正式协议需声明允许网络和信息源，审计额外信息，不以隐藏公开目标替代数据分离。

## 5. 基线、预算与校准

至少保留当前完整MILP参考求解器，报告 incumbent 与下界；另设简单可行启发式或短时求解基线。1月baseline在预算内未证明最优，不能把参考值误记为最优解。SCUC若被当前参考求解器饱和，先扩大难度或改为固定质量下的求解速度比较，不削弱强基线。

已有60秒/例与30分钟开发可作校准起点；包构建、预编译、加载、求解、输出的计时边界须明确。v0.1目标为开发墙钟限制、**无累计 token cap**，保留单响应上限和用量报告。其实现尚不能从HEFTCom的局部修复推断为已完成。最终实例执行时间、内存、开发时间和响应上限均待统一冻结。

## 6. 核心验收门槛

- 清洁环境构建并锁定Julia、包和求解器；在留出实例执行源码，而非复用已输出的排程。
- 独立检查负荷平衡、启停、爬坡、最小开停机、备用及任务实际包含的网络约束；重算成本。
- 无效排程、超时无 incumbent、资源超限与基础设施失败按固定合同分类。
- 同一参考方法在固定环境下满足声明的数值容差；记录最优性未知、有效下界及可能不可解实例。
- 数据有足够可行率与改进空间；任务包来源、许可、派生限额和安全范围全部可追溯。

## 7. 待定与阻塞项

UC为核心、SCUC为扩展的家族定位已确定。待定项是SCUC扩展的准入门槛、精确物理模型与难度校准范围，以及同系统/跨系统划分、实例数量、商业求解器独立赛道、归一化与容差。**首要协议缺口是终评执行算法和独立测试面板**，而非扩大n取值。
