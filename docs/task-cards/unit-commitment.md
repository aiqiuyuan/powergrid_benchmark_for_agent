# 机组组合：UC 核心与 SCUC 扩展

> 最新设计：见第13节“文献对齐的研究目标与配置”。主目标为完整约束下达到统一参考质量的求解加速；第一阶段仍是固定case算法演化。配置已整理，实际执行/校准未验收，`release_ready=false`。第3节保留2026-10-13历史证据，早期跨case草案不覆盖第12—13节。

## 1. 家族定位与研究能力

**家族 ID：`unit-commitment`。** UC为初始核心任务，SCUC为家族扩展。模型目标为最小运行成本；本任务的算法研究目标为在保持完整约束、达到统一近最优参考质量时减少求解时间。松弛与分解、暖启动、可行性修复、等价MILP formulation都可作为演化对象。固定时间后的成本/gap作为辅助指标。UC和SCUC不能在“五个家族”的计数中各占一项。

UC采用PGLib-UC的铜板网络实例。现有SCUC是派生的预防式DC线路约束版本，必须按适配定义命名；不能称完整AC或完整N−1 SCUC。

## 2. 演化对象与执行合同

- 演化对象：从标准实例输入生成排程的通用求解器代码、MILP建模、求解策略、初始化及后处理。固定预算内的结果可包含非最优的有效 incumbent。
- 提交产物：源码、依赖锁定、参数与随机种子；可包含公开训练数据产生的学习组件及其训练配方。禁止用按留出实例ID检索的预存排程替代求解。
- v0.1终评在新实例上**重新执行冻结求解器**，再由独立 verifier 检查排程并重算成本。现有先导 grader只解析排程，尚不满足此泛化合同。
- 指标：每例成本、可行率、参考 gap、求解时间、峰值内存及可获得时的有效下界。约束容差和缺失字段处理须固定；约10⁻⁷变化不能不经容差分析就称实质改进。
- 不同求解器的许可与资源须披露。跨实例主指标可采用相对固定参考成本的聚合，但同时提供原始成本、失败和未证明最优状态。

## 5. 基线、预算与校准

至少保留当前完整MILP参考求解器，报告 incumbent 与下界；另设简单可行启发式或短时求解基线。1月baseline在预算内未证明最优，不能把参考值误记为最优解。SCUC若被当前参考求解器饱和，先扩大难度或改为固定质量下的求解速度比较，不削弱强基线。

已有60秒/例与30分钟开发可作校准起点；包构建、预编译、加载、求解、输出的计时边界须明确。v0.1目标为开发墙钟限制、**无累计 token cap**，保留单响应上限和用量报告。其实现尚不能从HEFTCom的局部修复推断为已完成。最终实例执行时间、内存、开发时间和响应上限均待统一冻结。

## 6. 核心验收门槛

- 清洁环境构建并锁定Julia、包和求解器；在留出实例执行源码，而非复用已输出的排程。
- 独立检查负荷平衡、启停、爬坡、最小开停机、备用及任务实际包含的网络约束；重算成本。
- 无效排程、超时无 incumbent、资源超限与基础设施失败按固定合同分类。
- 同一参考方法在固定环境下满足声明的数值容差；记录最优性未知、有效下界及可能不可解实例。
- 数据有足够可行率与改进空间；任务包来源、许可、派生限额和安全范围全部可追溯。

## 12. 第一阶段：固定case算法演化（2026-10-15）

**用户已确认：第一阶段研究同一case上的算法演化，跨case泛化放到下一阶段。** 本节覆盖第10—11节及更早章节中与本阶段冲突的数据划分、免费完整评分和候选选择设计；不再以四个互不重叠面板或未见实例终评为本轮必要前提；相关数据与历史审计保留，供后续泛化研究复用。开发、框架过程反馈以及截止后冻结算法的独立复核运行使用同一目标case；这里“独立复核”指重新执行和评分，不指未见数据。允许针对固定目标case优化算法，结果只解释为该case上的演化能力；agent可访问哪些目标输入仍须按下述评分隔离政策核验。

共同研究设置保持T=43200秒、n=0／1／3／5／10、每档3次独立开发、累计token不限且不设累计token预留截断。**用户已确认：不向agent提供完整checker，禁止agent本地计算目标case的完整分数；开发过程中的完整目标评分只能调用框架评分器并消耗n。** 不得搜索原竞赛评测源码、复制／重写checker来取得完整目标评分，或绕过框架计数。语法、导入、输入输出格式检查及小型示例自检允许，但不能借此对完整目标case算分。目标case的数据可见范围、框架黑名单与实际隔离覆盖仍须核验；本节是已确认政策，不代表已经实现防绕过。

**取消免费public-selection完整算分。** agent在T内将最终版本放入原生artifacts路径，截止直接收集并冻结，不额外评分或登记候选；未修改时保留starter，产物缺失或损坏按失败处理。截止后冻结算法，由评分端重新执行终评；终评分数不反馈到开发过程，且不占过程n。n=0因此没有过程完整目标评分。各重复使用相同目标case、输入版本、评分与算法执行合同；开发重复和算法运行seed分别记录。12小时是算法开发上限，不是单次求解或评分预算。

**选case原则：优先选择任务集中难度最高的完整case。** 先以现成参考算法、原赛逐例结果及预先成本分析判断难度和可运行性；不能只按文件大小、原始目标数值或旧实验运行失败判难，也不能先观察哪个case的n效应最大再选。冻结具体ID前保留候选与取舍依据；若成本限制使最难候选不可执行，应公开原因及替代case。所有n档使用同一选定case，不因n增减约束、规模或算法执行预算。

| UC合同项 | 第一阶段要求 |
|---|---|
| 目标case | 一个完整原始PGLib-UC JSON；优先以现成完整MILP参考的求解状态、可证上下界及预先耗时分析选择高难case，具体ID尚未确认 |
| 完整性 | 保留原机组、时域、需求、备用、爬坡、启停与成本参数；不得裁时域、删机组或把派生SCUC约束并入原UC主线 |
| 执行与复核 | 围绕同一JSON开发并获取计n过程反馈；本地只做获准的语法、格式和小型示例检查；截止冻结算法后实际执行并由独立检查器验解，仍须修复当前只读取保存排程的评分路径；提交源码而非仅交排程 |
| 算法预算 | 先在完整case上测加载、建模、求解、输出及独立验解成本，再冻结预算、线程、容差和seed；旧60秒不自动成为本轮标准 |
| 参考比较 | 该库没有可直接插入的原竞赛排行榜；以同case、同合同的完整MILP参考及有证据的上下界比较，未证最优值不得称最优解 |
| 暂不要求 | 不以4／2／2／4日期拆分或同系统新日期泛化为本阶段前提；原始库及旧日期审计可留待下一阶段 |


可比较原赛公开的**同一case原始指标**；只有输入版本、评分、算法执行预算及环境能力相符时，才能称同条件比较，其余明确标为历史参照。单case成绩不能推出原榜总分、全任务族排名或跨case泛化结论。具体case ID、模型、实际资源及尚未确定的算法执行限额仍待证据冻结。

## 13. 文献对齐的研究目标与配置（2026-10-15）

### 13.1 研究问题和主指标

上层研究问题：**在相同开发时间下，计n评测反馈能否帮助Agent开发出更高效的UC求解算法？** 下层任务：对同一个完整原始UC case，保持所有约束，尽快达到统一近最优参考质量。模型的最小成本目标不变；算法性能以达标时间衡量。

主指标为具有可行性资格的PAR2；Reward由该指标单调映射。固定预算成本、公共下界gap、达标率和首个可行解时间分列为辅助指标。第一阶段的结论只覆盖固定case；后续泛化需要新的数据协议。

### 13.4 Reward与可解释结论

设在线时限为B，每次重放j第一次提交经独立验证的达标快照时刻为t_j。达标记`p_j=t_j`，未达标记`p_j=2B`，`PAR2=mean(p_j)`；不能删失败样本。全部重放均有合法输出、且无崩溃/OOM/资源违规才获得可行性资格，否则Reward为0。合格时：

`Reward = 1 - PAR2/(2B)`。

例如B=300秒，30秒达标得0.95，150秒得0.75，截止时达标得0.5；未达标得0。正式榜先按可行性资格、再按PAR2；达标率单列，不再另置于PAR2之前形成相反排序。0.5现在表示恰在时限达标，与旧成本映射中的0.5含义不同，历史Reward不重算、不跨版本比较。

该榜使用评测端离线参考L判断质量，**评价“达到参考质量的加速”，不评价候选自身证明最优性的加速**。若研究证明时间，须另测可信完整原问题上下界收敛；变量固定子问题的下界不能直接用于原问题证明。候选自报成本/下界/时间均不作为权威分数。

独立checker重算成本C；目标判断使用`C+max(0.01,1e-6*abs(U))`的保守成本裕量，原始成本/gap另报。MW容差、整数逻辑、低于参考下界的异常以及快照可信时间，按配套合同统一检查，尚待运行边界验证。

### 13.5 怎样确保参数合理

**文献依据不替代实测。** 发布前在最终硬件上，B0/Tight/Random1按同一个case、3个固定solver seed校准，完成原模型等价与成本核对。准备门槛为：至少一种强基线3/3达标；最快合格基线中位时间在5秒至时限80%之间；非优化开销不超过中位端到端时间20%；内存适配8GiB。这些门槛是本项目工程判断，并非论文要求或当前已测结论。

若过易、全不达标、参考太松或主要在测JIT，应在Agent实验前修改准备版本/资源/选例并记录原因，而非削弱基线或在正式成绩出来后换case。原始参数与全部约束保留；不同n使用同一冻结合同。报告完整逐次结果和运行波动，三次开发不预设有足够统计功效。
