## 1. 实际完成范围

新增可移植原生任务包 [rte-maintenance-abc-x15-v2](../task-packages/rte-maintenance-abc-x15-v2/README.md)，基于v1已跟踪源码构建；不携带巨型数据、私有框架、服务凭据、模型轨迹或原始X成绩。未修改v1任务包及原149文件源码锁。

本轮只改必要任务逻辑：面板聚合、完整反馈、指标名、ABC公开助手、题面及冻结工具；启动、agent、计n、截止与原生终验继续复用eval-in-loop／Harbor。没有增加新的评分网关、计数服务或自动回滚历史最好候选的机制。

| 内容 | 已实现行为 |
|---|---|
| 主排行 | 可行例数k优先；相同k再比较Q=sum(有效q)/15 |
| 标量 | reward=(k+Q)/16，指标名rte_x15_coverage_quality_900_v2 |
| 逐例目标 | 官方F、mean_risk、expected_excess和q；其他例失败也返回有效例目标 |
| 失败目标 | 目标字段为null，汇总质量贡献0，不制造有效目标值 |
| 反馈诊断 | 完整15例，AC／WA／RE／TLE、固定约束错误类别、退出码、候选墙钟、子进程RSS及单位 |
| 身份与完整性 | 候选SHA256、900秒预算、面板数量、evaluation_completed、汇总与逐例一致性 |
| 隐私与大小 | 只组装白名单字段，JSON完整且不超过16KiB；不返回输入、解、原日志、checker原文或私有路径 |
| 基础设施故障 | evaluation_completed=false，诊断单列；不伪装为15例候选失败或可用零分 |
| 公开ABC助手 | 使用相同聚合语义，分母是所选ABC面板数量，不能直接当X15成绩 |
| 冻结双档 | 同一候选摘要和receipt绑定两档；900秒主成绩、5400秒补充，不取最大值 |

`validity`及私有`reward-details.valid`继续表示全部实例可行；它们为false时，一次完整的部分可行评测仍可能有正reward。实际读取时应结合`evaluation_completed`、`feasible_count`及`all_cases_feasible`，避免再次把部分进步归零。
