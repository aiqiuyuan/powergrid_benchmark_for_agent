## 2. 明确了什么规则

- 五task的n=0／1／3／5／10，各3次独立开发，共75个run；开发上限12小时，累计token不限且无累计预留截断。
- 不给开发agent完整checker，禁止本地完整目标case评分、重写checker绕计数，以及搜索下载原赛测评源码。完整目标过程反馈只能通过框架评分器消耗n。
- n是最多受理的完整评分作业数，受理／完成／投递分别记录；不能把“配置n次”当作“收到n条有效反馈”。
- 语法、导入、格式及小型示例检查允许，solver内部优化计算正常；不能借这些入口取得完整目标case反馈。
- 不再安排免费的public-selection／best-public-selection完整评分。agent依据已经计n取得的反馈保留最终版本，T截止冻结原生artifacts，无修改保留starter。
- 截止后仅复核唯一冻结算法，不占过程n、不回流开发、不按终验结果更换版本；n=0也保留这次最终复核。
- 与原榜优先比较同一case原始值，披露时间／环境／信息等差异，不把单case结果推导成原赛总榜名次。UC没有原竞赛榜，改报完整参考方法及可信下界。
