# v2部署边界

复用原生eval-in-loop／Harbor生命周期。只替换本v2任务包、相应指标、题面及验收，不新增评分网关或计数服务。n=0／1／3／5／10各3次，43200秒开发上限，token累计不设上限；开发2CPU／32GiB，verifier15CPU／256GiB，候选单核／16GiB地址空间。

外层至少21CPU／296GiB，保留原有4CPU／8GiB运行开销。磁盘部署使用经校验的ephemeral request／limit、Docker卷限额与健康节点规则；这些是部署修复，不增加科学实验的候选或开发内存预算。v2需要自己的源码和镜像来源凭据，不能复用只允许七个旧槽位的恢复提交器。

模型CLI应在可信基础镜像预装；开启原生egress和已验证来源阻断，禁用agent WebSearch／WebFetch。开发镜像不含X、参考解、历史实验产物、inventory或私有报告。原始ABC/checker可自由本地使用。网络控制是辅助边界，仍需可信operator验证代理、直连和允许路由。

原生PersistentAgent的1800秒终验余量影响开发结束前是否续跑；保留原行为和真实时长记录。受保护900秒反馈只经现有n账本；终验900秒为主成绩，不回流。5400秒由开发结束后对同一摘要离线执行，仅作补充。最终为截止工作区，不按历史最好反馈自动回滚。

内存审计应区分公开ABC辅助子进程OOM后完整生命周期仍完成，与整个开发／verifier无法完成。补充审计保留全部OOM证据，不静默把OOM抹去，也不对某个n组单独加内存。正式结果应分别报告基础设施失败、算法失败与完成状态。
