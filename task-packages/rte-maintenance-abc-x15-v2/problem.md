# RTE 2020 电网检修排程

## 1. 任务

来源为 ROADEF/EURO 2020、法国输电运营商 RTE 的公开检修排程题。为每个检修作业选择一个整数开始时段，执行期间不能中断；起点不同，持续时间、资源使用和风险可能不同。它是带资源上下界、季节性互斥和情景风险的组合优化问题；不在本任务内重新求解潮流。

输入使用官方 JSON：Resources、Seasons、Interventions、Exclusions、T、Scenarios_number、Quantile、Alpha。每个实例是一项独立求解任务。某个资源/时段/起点缺失的 workload 按官方规则视为零；risk 的情景顺序必须保留，不能把各检修独立分位数相加。

接口：`python solver.py --instance /absolute/instance.json --output /absolute/schedule.txt --time-limit 898 --seed 2020`。必须从传入路径读取数据。输出每行 `intervention_name start_time`，每项检修恰好一次；正式打分时不接受自报分数。

## 2. 硬约束

- 整数开始时间在 1..tmax 内，且检修全部在 T 以内结束。
- 每个资源在每个时段的总占用同时满足下界与上界。
- 指定季节内互斥的检修不能重叠。
- 使用官方 checker 的资源容差 1e-5；补充严格检查输出完整性、重复项、数值格式和结束时刻。

## 3. 目标与评价

对每个时段 t，先按情景累加所有正在进行的检修风险，得到 R[t,s]。其情景均值为 m[t]，按照官方排序下标 ceil(S[t]*Quantile)-1 得到 q[t]。

最小化官方目标：`F = Alpha * mean_t(m[t]) + (1-Alpha) * mean_t(max(0, q[t]-m[t]))`。这里的 expected excess 是“分位数减均值的正部”，不是 CVaR。

任何硬约束失败都没有有效官方目标。每个可行例质量为 `q = 0.5 - atan(F/scale)/pi`（实现保留数值稳定分支）；scale仅由输入计算并冻结。X15主排行先比较可行例数k，再比较 `Q=sum(有效例q)/15`。无效例质量贡献0，不计算伪目标值。框架奖励 `reward=(k+Q)/16` 编码这个顺序；一个额外可行实例优先于任何质量变化，相同覆盖时F改进提高Q。全部可行时Q等于原有效质量均值；reward不是Q、官方F或历史竞赛积分。公开ABC工具沿用同一规则，但分母是所选ABC面板大小，不能与X15直接混比。

反馈为完整15例的结构化JSON；有效例即使其他例失败也返回F、mean_risk、expected_excess与q，无效例这些字段为null。另含AC／WA／RE／TLE、固定约束错误计数、退出码、候选墙钟、子进程峰值RSS及单位、候选摘要与面板汇总。原始输入、解文件、候选stdout/stderr、checker原文及主机路径不返回。评测基础设施失败单列evaluation_completed=false，不伪装为算法0分。
## 4. 本版数据范围

协议为 rte2020-abc-x15-v2：A/B/C 各15例，共45个原始实例及官方 checker 全部开放，可本地任意开发和评分；X的15个原始实例仅在隔离 verifier 中。每次受保护反馈都会完整评估 X15，15个独立进程并行，每例900秒墙钟、1个独立CPU、16GiB地址空间上限，无GPU。启动、导入、实例解析、求解和写出都计入900秒；数据复制、官方检查另有基础设施预算并记录耗时。

主成绩为原生开发截止后900秒/例终验，不向开发agent回流；截止工作区冻结为最终源码，框架不会自动按历史最好反馈回滚。开发终止后，再独立离线以5400秒/例评估同一冻结源码，结果仅作补充、不占n、不回流、不用于选优。X参与了受限自适应反馈，所以最终结果只能称为“输入受保护的同面板冻结重评”，不能称为从未使用的独立测试集。官方数据历史公开，亦可能被预训练接触。资源与部署验收应以本批v2的独立记录为准，不能宣称与历史竞赛平台等价。

## 5. 初始方法与演化范围

初始单文件求解器继承旧先导任务，使用 SciPy/HiGHS MILP 优化均值风险，然后按真正的情景分位风险做可行坐标搜索；尚未验证能在ABC45/X15全部找到可行解。允许 agent 自主修改模型构造、初始化、邻域、修复与搜索策略，最终提交一个自包含 Python 文件。不得读取受保护评分环境、检索X数据/参考答案/旧实验结果，或绕过反馈次数和资源限制。它演化的是排程算法，并不要求训练 RL 模型。
