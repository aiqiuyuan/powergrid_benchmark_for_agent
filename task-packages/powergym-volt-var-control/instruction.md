# PowerGym 混合设备 Volt-Var 控制算法开发

这是公开题面与接口准备版，**尚未冻结目标 case、原生/物理适配轨、资源、完整 runner 或评分参数，不能直接启动实验**。你将开发可执行控制算法，联合控制电容器、调压器和电池，管理电压、实际有功损耗、设备操作和跨时段能量。默认推理阶段不调用在线 LLM。

## 提交与接口

编辑 `/app/submission/` 内算法；完整依赖、参数、权重和辅助文件都须位于 artifacts 会收集的该目录。入口为 `controller.py`：

```python
class Controller:
    def __init__(self, metadata): ...

    def act(self, observation):
        return flat_action
```

同一完整 episode 内可在实例中保存历史，作业之间新建实例。metadata 包含 `capacitor_count`、`regulator_count`、`battery_count`、`continuous_batteries`、`tap_max`、`battery_max`；设备顺序、容量、单位和额外信息由实际 release 冻结。

扁平动作依次为 **电容器、调压器、电池**：

- 电容器为整数 0/1。
- 调压器为 0 到 `tap_max` 的整数档位；上游候选默认最大值 32。保持当前状态时应读本步观测，不写死初始 tap。
- 离散电池为 0 到 `battery_max` 的整数档位；默认最大值 32，idle 是 16。
- 连续电池 `_cbat` 为 [-1,1] 有限数，idle 为 0。

starter 使用 `observation["capacitor_states"]` 与 `observation["regulator_taps"]` 保持当前设置，并为每台电池返回 idle。**全零动作不是 DoNothing**。可信侧必须在写设备前检查长度、整数性、有限数与范围；不能依靠静默投影把非法命令当合法动作。

正式控制器接收当前设备状态、电池 SOC/实际功率以及获准电压等集中观测；当前负荷、时刻和预测是否开放须在 release 对所有方法一致声明。完整 OpenDSS/PowerGym Env 对象与全日未来数组不能直接交给候选；历史只来自已发生的合法观测，不能读未来真实负荷。

`/app/public/toy.json` 与 `/app/support/check_interface.py` 只做合成接口调用，不包含目标数据、OpenDSS 潮流、SOC 动态或评分。通过它们不代表真实控制有效。

## 原生轨与物理适配轨

发布时必须选择并命名一个轨道，不能混排：

- 原生轨保留锁定上游设备、能量账本、动作、有效权重及 native return，明确 vanilla / `_soc` / `_cbat`。vanilla 没有终端 SOC 代价；`_soc` 为软代价，不是末 SOC 硬等式。
- 物理适配轨另行冻结初末 SOC、容差、效率、P/Q 关系、失败处理及主指标，所有方法在同合同重跑；不能沿用论文分数或仍称原生复现。

本准备版没有自行指定末 SOC 公差、效率或 reward 权重。不能仅靠耗尽初始电池获得高 native return，就声称实现了可持续低损耗控制；实际结果必须同时报告每台电池初末能量和动作/实际功率。

## 开发、反馈与终评

第一阶段使用预先固定的完整 case：同一网络、完整运行日/时域、冻结负荷、初态、设备、轨道与评分合同。开发反馈和最终复核都用该 case，研究同 case 算法演化，跨 case 泛化另行研究。

开发上限 12 小时，不设累计 token cap。完整目标过程反馈仅通过框架计数入口，最多受理 n 次；n=0 是没有完整目标过程反馈。候选错误、超时与非法输出消耗已受理次数，基础设施故障按同一逻辑作业恢复。允许语法/导入/格式/toy 检查，不提供免费完整 public-selection 或本地完整目标评分。

禁止通过下载完整原始目标数据/仿真器、搜集 checker、观察完整 reward/损耗日志或额外运行路径绕过计数。候选在可信执行阶段可以使用获准当前信息做内部计算或搜索，但不能将完整目标轨迹和等价分数回传开发端；实际工具、网络和文件限制由发布环境验收。

截止时只收集 `/app/submission/` 的唯一最终源码、依赖、参数和权重；不能以保存好的动作轨迹替代算法。无修改保留 starter。可信侧在同 case 重执行冻结候选并独立计分，不回流开发、不占过程 n、不择优重跑。

模型、CPU/GPU/内存、逐步和整例时限、搜索权限、反馈字段/精度、reward 映射及失败处理需在真实 release 冻结。本题面不提供未校准的默认配额。

## 原始指标

至少保存全电路实际有功损耗电量 kWh、相位×时间电压合规率/最大违约、电容器切换、tap 移动档数、命令与实际电池功率、吞吐量、每台初末 SOC、完成步数与求解收敛。原生轨另保存准确 native return 和有效权重，适配轨使用独立冻结指标。

reward、源端有功归一化损耗比与实际 kWh 不能混称。不可采信候选自报分数；不收敛、非有限、时序越界、超时和能量违规按预定合同处理。不得通过提前失败截短时域逃避后续代价。缺少可信数据/依赖/runner 是基础设施失败，不构造算法成绩。
