# MAPDN 局部电压控制算法开发

这是新增任务的公开题面与接口准备版，**尚未冻结目标 case、资源、完整 runner 和计分配置，不能据此启动正式实验**。实际启动前，出题侧须提供已验收 release；以下合同不能替代运行证据。

你的目标是改进光伏逆变器无功控制算法，在允许的局部观测下控制全网电压并减少实际有功损耗。最终提交的是算法源码及获准依赖/参数/权重，不是保存好的目标动作轨迹。默认推理阶段不能调用在线 LLM。

## 文件与接口

可编辑算法位于 `/app/submission/`；完整依赖、权重与必要辅助文件也必须放在将被 artifacts 收集的该目录。starter 为 `/app/submission/controller.py`：

```python
class Controller:
    def __init__(self, metadata): ...

    def act(self, observation):
        return normalized_actions
```

每个分配控制单元有独立 `Controller` 实例；历史可以保存在实例中，作业之间清空。`metadata` 包含该单元获准的 `actor_id`、`pv_count`、`action_bound` 以及发布版列明的局部设备容量/索引。starter 还支持可选 `droop_gain` 与 `target_voltage_pu`，它们是算法参数，不是权威评分定义。

`observation["pv_voltage_pu"]` 是本控制单元所分配 PV 的当前电压列表。返回值必须是长度恰好等于 `pv_count` 的扁平列表，每项为有限归一化命令，满足 `abs(a) <= action_bound`。可信运行器按每台设备当前有功和额定容量将命令映射为无功；候选不能修改额定容量或动作界。上游归一化范围是有符号区间，不能误写为非负 0–1。

正式局部主线拟采用每逆变器一个单元的 `distributed` mode。完整区域观测的字段、时标、单位、历史窗口、设备顺序与可见静态信息须随 release 另行冻结；不得通过观察 starter 的 toy 输入推定完整区域接口已经接好。区域控制、通信或集中式参考使用另行声明的权限。

`/app/public/toy.json` 只供导入、调用、动作长度与有限数检查，没有目标轨迹、潮流模型或真实评分。可以使用它做接口测试；通过 toy 不能证明电压合规、网损改善或完整时域有效。

## 信息与工具权限

- 只读取分配给本单元的当前观测、允许的局部元数据和自身历史；不能读取其他单元内存、全网状态、未来负荷/PV 或可信 evaluator 文件。
- 可共享离线训练参数；运行时通信只有在 release 明确允许并规定预算后才能使用。
- 可执行正常算法内部计算和获准模型上的物理估计；不得利用环境副本、公开原始目标数据或日志重建完整目标评分并回传开发端。
- 开发端不提供完整 checker 或目标评分工具，也不允许搜索/下载原测评源码绕过计数。实际文件、网络和工具设置须由已验收运行环境落实。

## 开发反馈与最终提交

本阶段在一个预先固定的完整 case 上开发、计数反馈和最终复核，研究同 case 算法演化。每次开发上限 12 小时，不设累计 token cap。完整目标过程反馈仅来自框架，最多受理 n 次；n=0 明确为没有完整目标过程反馈。候选错误、非法动作或超时消耗已受理次数，基础设施恢复按同一逻辑作业规则处理。

不能免费运行完整 public-selection。你可根据已经取得的计数反馈决定保留版本；截止后冻结 `/app/submission/` 的唯一最终版本，没有修改则沿用 starter。最终由可信侧在同 case 执行并独立评分，不回流开发、不占过程 n、不择优重复。

正式运行前须填实模型、资源、逐步与整例时限、反馈字段和精度、失败分以及候选包范围。本准备版没有提供这些未校准数值，不代表任意运行成本被允许。

## 物理指标

权威结果由可信侧独立计算，至少包括全母线同时合规的时间比例、母线×时间越界比例、最大过压/欠压、实际总有功损耗 MWh、非法动作、不收敛和完成间隔数。Q 使用量与训练 reward 单列，不能冒充真实网损；损耗需覆盖实际网络中的变压器等有损元件。

最终排名规则、容差、reward 映射和失败处理待 release 冻结，不采信候选自报分数。不得通过提前崩溃或输出非法动作截短完整时域来逃避后续代价。数据/solver/运行器缺失属于基础设施失败，不能据此推导算法成绩。
